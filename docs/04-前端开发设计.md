# 前端开发设计

## 一、工程结构

前端是一个 Next.js（App Router）应用，目录按「路由 / 组件 / 状态 / 数据 / 类型」分层组织，确保画布、对话、主页三条线各自内聚而又共享基础设施。

`app/` 目录承载路由。其下 `(marketing)` 或根级放置登录与认证回调路由；`page.tsx` 是主页（服务端组件外壳）；`p/[projectId]/page.tsx` 是设计页（加载初始数据后挂载客户端画布工作台）；`auth/callback` 处理 OAuth 回跳；`layout.tsx` 提供全局外壳、字体、主题与国际化上下文。

`components/` 目录按领域分子目录。`canvas/` 放画布相关组件：画布容器、各类自定义节点、节点浮动工具条、缩放手柄封装、底部工具栏、左下控件簇、背景与对齐参考线。`chat/` 放对话面板相关组件：面板容器、消息列表、消息气泡（用户 / 智能体 / 生成进行态）、对话输入框、提及选择器、附件上传、Agent 模式下拉。`home/` 放主页相关组件：标语区、创作输入框、模型与场景选择条、最近项目网格、项目卡片、新建项目卡片。`ui/` 放跨领域的通用基础组件（按钮、弹层、下拉、骨架屏、提示条），统一视觉语言。`shared/` 放跨界面共用的信息簇（头像菜单）。

`stores/` 目录放客户端状态库：画布状态库、对话状态库、会话 / 用户状态库。`lib/` 目录放数据与工具：Supabase 客户端工厂（浏览器端、服务端、中间件三种形态）、Realtime 订阅封装、媒体上传封装、Edge Function 调用封装、坐标变换与画布几何工具、节点与数据库行的双向映射器、各类领域钩子（项目、画布、会话、生成）。`types/` 目录放贯穿前后端的共享类型定义（节点判别联合、消息、生成、模型目录、各 Edge Function 的输入输出契约）。`i18n/` 放中英文案与语言切换逻辑。

## 二、渲染策略

主页采用服务端直出与客户端交互混合。服务端组件在请求时携带用户会话查询用户档案与项目列表，直接渲染标语区与最近项目网格的初始内容，首屏无需等待客户端取数；其中的创作输入框、选择条、卡片悬停操作以客户端组件嵌入。发起创作的写操作经服务端动作完成「建项目 + 记首条消息 + 建首个生成任务」后服务端重定向到设计页。

设计页采用「服务端预取 + 客户端水合」。服务端组件先取项目元信息、画布节点与边、会话历史等初始快照，作为属性传给客户端的画布工作台组件；工作台挂载后用快照初始化状态库、建立 Realtime 订阅，之后的一切交互与同步都在客户端发生。画布与对话因高度依赖浏览器能力而整体为客户端组件，不做服务端渲染。

## 三、状态管理

客户端状态以轻量状态库（Zustand 模式）维护，分三库。

**画布状态库**持有节点集合、边集合、当前视口、选择集（被选中节点 id 列表）、当前激活工具、以及交互瞬态（正在框选的区域、正在绘制的临时形状 / 路径、对齐参考线）。它向组件暴露读取与一组语义化动作：添加 / 更新 / 删除节点、设置选择、切换工具、提交本地变更、应用远端变更。它是画布交互的单一事实来源在客户端的投影。

**对话状态库**持有当前会话的消息流、正在流式接收的助手回复缓冲、输入框草稿、当前所选模型与 Agent 模式、待发送的提及与附件。它协调「乐观追加用户消息 → 触发生成 → 流式 / 实时更新助手消息与生成态」的时序。

**会话 / 用户状态库**持有登录用户档案、语言偏好等全局信息，供信息簇与各处消费。

三库与后端的协调遵循「乐观更新 + 防抖持久化 + 实时回流校正」三段式。本地交互先即时更新状态库给出零延迟反馈（乐观）；高频连续变更（拖动、缩放）在交互结束或防抖窗口到期后才经 PostgREST 持久化（防抖），避免写入风暴；远端经 Realtime 推来的变更与本地版本按更新时间比较，较新者覆盖较旧者（回流校正），保证多设备一致与生成结果落地。乐观更新失败（写库报错）时回滚本地状态并提示。

## 四、无限画布（React Flow）工程设计

无限画布是产品的核心，以 `@xyflow/react` 的 ReactFlow 为底座。本节是全套文档对画布的权威设计。

### 4.1 以 React Flow 承载自由设计画布的取舍

React Flow 的设计初衷是节点图（流程图、连线图），而本产品需要的是 Figma 式的自由设计画布（元素自由摆放、可旋转缩放、以前后层级而非连线为主）。选择以 React Flow 承载，是为了直接复用其成熟的无限视口（平移 / 缩放）、坐标体系、节点选择与拖拽、自定义节点渲染、节点缩放手柄、仅渲染可视节点的性能机制，从而把自研成本压到最低。代价是：连线（edge）退居次要、节点旋转与多选整体变换需自行补足。设计据此把每个画布元素建模为一个 React Flow 自定义节点，边仅用于记录可选的生成血缘关系，旋转与组变换以自定义机制实现（见 4.5、4.6）。

### 4.2 坐标系与变换

画布存在两个坐标系：**屏幕坐标**（像素，随窗口）与 **flow 坐标**（画布逻辑坐标，与缩放平移无关）。节点的位置以 flow 坐标存储于 `canvas_nodes.position_x/y`，与视口解耦，从而缩放平移不改变节点逻辑位置。一切「在某屏幕点落一个新元素」的操作（点击落文本、拖入图片、绘制起点）都须先把屏幕坐标经 React Flow 提供的屏幕到 flow 坐标的换算（`screenToFlowPosition`）转为 flow 坐标再写入节点。反之，需要把节点位置映射到屏幕（如定位浮动工具条）时走 flow 到屏幕的换算。所有几何工具集中在 `lib` 的坐标变换模块，避免散落各处导致的坐标系混用错误。

### 4.3 视口管理

视口由平移量与缩放比构成，采用「受控」方式：视口存于画布状态库并与 `projects.viewport` 持久化，进入项目时恢复上次视口，平移缩放结束后防抖写回。缩放限制在合理倍率区间（设下限与上限），缩放步进平滑；左下角「100%」显示当前缩放，点击展开预设倍率与「适应画布」（`fitView`，把全部节点纳入视野并居中）。空画布给出居中的引导语与默认视口。视口的滚轮 / 触控板缩放、空格 / 中键拖拽平移、双指手势均由 React Flow 原生提供并按产品手感微调（缩放灵敏度、平移阻尼）。

### 4.4 自定义节点体系

通过 React Flow 的节点类型注册（nodeTypes）声明本产品的全部节点类型，与 `node_type` 枚举一一对应。

图片节点渲染一张图片，支持裁剪、滤镜、圆角、透明度等展示属性，媒体经签名 URL 加载并配缩略图占位与渐进加载。文本节点渲染可就地编辑的富文本框，承载字体、字号、字重、行高、对齐、颜色等排版属性，进入编辑态时拦截画布的拖拽与快捷键以免冲突。形状节点以内联 SVG 渲染矩形 / 圆 / 多边形等，支持填充、描边、圆角。手绘节点以 SVG 路径渲染笔迹，路径由手绘交互采样的点序列平滑而来。视频节点渲染视频播放器，支持封面帧、自动播放 / 静音、播放区间。生成占位节点渲染一个带进度与提示词摘要的占位卡片，订阅其关联生成任务的进度；任务成功后该节点被原地转化为图片 / 视频节点。画板节点渲染一个固定尺寸的边框容器，可作为其他节点的父容器，承载分组与导出边界语义。

每个自定义节点以记忆化（memo）封装，仅在自身数据变化时重渲染，避免一处变更引发全画布重绘（见 4.8）。

### 4.5 节点变换：缩放与旋转

缩放借助 React Flow 的节点缩放手柄（NodeResizer）实现，选中节点时四角与四边出现手柄，拖拽改变节点宽高并写回 `width/height`；支持等比（按住修饰键）与自由两种模式，并设最小尺寸约束。

旋转是 React Flow 未原生提供的能力，需自行补足。设计为：在选中节点上方渲染一个旋转手柄，拖拽时计算节点中心到指针的角度，写入 `rotation`；节点内容容器据 `rotation` 施加 CSS 旋转变换。需注意旋转引入的两个工程点——其一，旋转后元素的视觉包围盒与 React Flow 用于命中测试和缩放手柄定位的轴对齐盒不一致，缩放手柄与命中区域需在旋转坐标系下重新计算或对旋转节点采用近似策略；其二，旋转与缩放叠加时变换顺序须固定（先缩放后旋转或反之需统一），避免抖动。该机制集中实现于一个「可变换节点」高阶封装，所有需要旋转的节点类型复用之。

### 4.6 选择与组变换

单选由 React Flow 原生支持，点选即选中并显示手柄。多选支持框选（拖出选择框圈选）与加 / 减选（按修饰键点选）。被多选的节点作为一个临时组：整体拖动时所有成员同步位移；整体缩放时以组的包围盒为基准等比缩放各成员的位置与尺寸。由于 React Flow 不原生提供「组整体缩放手柄」，组变换由自研的「选区变换层」实现——它根据选择集计算组包围盒、渲染组级手柄、在拖拽时把组变换分解为对各成员位置 / 尺寸的批量更新，并作为一次批量本地变更提交（结束后批量持久化）。复制 / 粘贴在选择集上操作，粘贴时以小偏移落新节点并入选。

### 4.7 层级与图层控件

节点前后顺序由 `z_index` 决定，渲染时按 z_index 排序。浮动工具条与左下图层控件提供「置顶 / 置底 / 上移一层 / 下移一层」，通过重排选中节点的 z_index 实现。左下角的图层堆叠图标展开一个轻量的当前画布元素列表（按 z_index 倒序，显示类型图标与名称 / 缩略），支持点选定位、拖拽改序，但刻意不做成完整的图层树编辑器（分组、嵌套、可见性逐项管理等不在范围内）。

### 4.8 背景、网格与对齐

画布背景以 React Flow 的 Background 组件渲染，支持点状 / 线状 / 无三态，由工具栏的「画板 / 网格」工具切换显隐与样式。元素拖动时提供对齐参考线与吸附：拖动节点时实时计算其边与中线同其他节点 / 画板的对齐关系，达到阈值时显示参考线并吸附到对齐位置，提升排布精度。参考线与吸附逻辑在拖动事件中计算，结束后清除。

### 4.9 工具栏与画布交互状态机

底部工具栏的十个工具背后是一个画布交互状态机，当前激活工具存于画布状态库，决定指针在画布上的行为。

选择 / 移动工具是默认态，指针用于选中、拖动、变换节点与（在空白处）框选；抓手 / 定位工具把指针变为纯平移，画布拖拽即平移视口。上传图片工具触发本地文件选择，选定后经媒体上传封装上传到 uploads 桶、建资产、在视口中心（或用户指定落点）以 flow 坐标创建图片节点。画板 / 网格工具创建一个固定尺寸的画板节点并切换背景网格。形状工具进入绘制态，在画布上按下并拖拽，依拖拽矩形实时创建并调整一个形状节点，松开提交。画笔工具进入手绘态，按下拖动持续采样指针点形成路径，松开把平滑后的路径提交为手绘节点。文本工具进入落字态，点击落点以该 flow 坐标创建一个空文本节点并立即进入编辑。AI 图像 / 视频 / 文本三个工具调起对应模态的生成：它们或在画布上先落一个生成占位节点、再把生成请求交由对话 / 生成流程驱动，或唤起一个轻量提示词输入再提交；提交后的异步推进与落地复用统一的生成流水线（见第 05 篇）。

工具完成一次创建后一般自动回落到选择工具（可配置为连续创建模式）。每个工具的进入 / 退出、指针事件处理、临时态渲染、提交逻辑被组织为状态机的清晰转移，集中维护，避免散落的条件分支。

### 4.10 性能策略

画布须在数百至上千节点下保持流畅，性能策略有五。其一，开启 React Flow 的「仅渲染可视区域元素」，视口外节点不进入渲染。其二，每个自定义节点记忆化，节点级状态隔离，避免单点变更触发全量重渲染；选择集、视口等高频变化的状态以选择器（selector）细粒度订阅，组件只订阅自己关心的切片。其三，高频交互（拖动、缩放、绘制）的中间态只更新本地、不写库，结束 / 防抖后才持久化与（必要时）广播。其四，大量图片节点采用缩略图 + 渐进加载 + 懒加载，原图仅在需要时取，借助 Storage 图片变换与 CDN 降低传输。其五，初始加载大画布时分批 / 按视口优先加载节点，先渲染视口内、再补齐其余，避免首帧长阻塞。

## 五、前端实时同步

设计页挂载后，画布工作台通过 Realtime 订阅封装订阅本项目频道，监听 `canvas_nodes`、`canvas_edges`、`generations`（及按需的 `messages`）的行变更。收到节点插入 / 更新 / 删除事件时，映射为本地节点的增改删并按「较新覆盖较旧」校正本地状态；收到生成任务状态 / 进度变更时，更新对应占位节点的进度展示，成功事件触发占位向真实节点的转化、失败事件给出可重试提示。订阅在离开项目时释放。为区分「本地乐观更新已反映的变更」与「真正来自远端的变更」，本地提交的变更携带客户端标识 / 版本，回流时据此避免对自身刚做的更新做无谓的二次套用（回声抑制）。

## 六、对话与 Agent 面板实现

对话面板以对话状态库为数据源。消息列表按时间渲染用户、助手与生成进行态三类气泡，列表随新消息自动滚动到底（用户上滚浏览历史时暂停自动滚动）。发送流程为：用户在输入框成稿（可经提及选择器插入 `@` 节点引用、经「+」上传附件、经 Agent 下拉选模式 / 模型）→ 点击发送或回车 → 乐观追加一条用户消息、清空草稿 → 调用提交生成 / 编排的 Edge Function → 面板出现助手进行态、画布出现占位 → 结果经流式（文本）或 Realtime（图 / 视频落地）回流，逐步把进行态更新为完成态。

提及选择器在键入 `@` 时弹出，列出当前画布节点（按类型分组、带缩略图与名称），选中即把节点引用并入待发送列表，渲染为输入框内的可删除标签；提交时这些引用作为参考素材随消息传给生成流水线，用于针对画布上具体元素的再生成 / 编辑。Agent 模式下拉切换工作模式（纯生成 / 编排式智能体 / 场景流程），并隐含所用生成模型；其取值与主页选择条共享模型目录。附件上传与画布的图片上传共用媒体上传封装，上传后以资产引用并入消息。

## 七、主页实现

主页标语区为静态展示。创作输入框为多行自适应文本域，左下「+」复用附件上传，右下发送按钮在内容为空时禁用；模型与场景选择条由模型目录数据驱动渲染，模型为单选高亮、场景为单选，所选作为创建项目的初始上下文。最近项目网格首位固定新建项目卡片（点击即建空项目并进入设计页），其后由服务端预取的项目列表按更新时间倒序渲染卡片（缩略图 + 项目名 + 更新时间），悬停浮现重命名 / 删除；项目较多时分页或滚动加载，增量拉取。发送创作的动作完成建项目、记首条消息、建首个生成任务后跳转设计页，使用户进入即见生成。

## 八、认证与受保护路由

认证基于 Supabase Auth。登录页提供邮箱 / 魔法链接 / OAuth 入口；OAuth 经回调路由完成换取会话。会话以 Cookie 持有，经 Next.js 中间件在请求边界校验与刷新令牌，未登录访问主页 / 设计页时重定向到登录。服务端组件、服务端动作、客户端组件分别使用对应形态的 Supabase 客户端持有会话，确保 RLS 上下文在三种运行环境下都正确建立。头像菜单提供退出登录与设置入口。

## 九、加载、空态与错误处理

每个数据视图具备三套反馈：加载态以骨架屏呈现（主页项目网格骨架、设计页画布与对话骨架）；空态给出引导（主页无项目时突出新建、设计页空画布的引导语、对话无消息时的「What do you want to create?」）；错误态给出可读信息与重试入口。生成的进行态以进度与缩略预览呈现，失败可一键重试。媒体加载失败给出占位与重试。所有破坏性操作（删元素、删项目）可撤销或二次确认。网络异常时本地编辑不丢失，恢复后补同步。提示统一经轻量提示条（toast）呈现，避免打断创作。

## 十、国际化

界面文案经 i18n 模块管理，支持简体中文与英文切换，用户偏好存于 `profiles.locale` 并随会话恢复。尊重界面草图既有的中英混排现状：产品标语、模型名、Agent、部分英文引导语保留英文原文，功能性与正文文案以所选语言呈现。日期、数字按区域格式化。

## 十二、工程规范

实现遵循统一工程标准：全量 TypeScript 严格模式，禁止任何简化实现、占位符与 TODO；公共函数、类型、组件与钩子均具完整 JSDoc，关键行内注释用中文；节点类型、消息、生成、模型目录等贯穿前后端的类型集中于 `types/` 并在前端与 Edge Function 间共享，杜绝重复定义与漂移；坐标变换、行与节点映射、Supabase 访问、Realtime 订阅等基础设施统一封装、单点维护；同一特性涉及的多文件成套交付；命名、目录与风格由 ESLint 与 Prettier 强约束。画布几何、变换与状态同步等易错处需配套充分的单元 / 集成测试，确保坐标系不混用、乐观更新与实时回流不互相覆盖。
