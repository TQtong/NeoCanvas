# v0.2.0 数据模型与生成事务

## 一、目标

为图片编辑建立可审计、可重试、具备 RLS 保护的输入血缘，并在不破坏旧生成记录的前提下扩展 generation 操作语义和候选采用事务。数据库继续作为唯一真相来源，客户端不得直接拼装编辑结果状态。

## 二、资产扩展

`assets` 增加字段：

| 字段           | 类型      | 约束                     | 语义                                           |
| -------------- | --------- | ------------------------ | ---------------------------------------------- |
| `is_auxiliary` | `boolean` | `not null default false` | 是否为蒙版、合成输入或按模型限制生成的输入副本 |

在 `(project_id, is_auxiliary, created_at desc)` 建立索引。普通素材查询显式使用 `is_auxiliary = false`；节点绑定资产、generation 输入和服务端审计查询不应用该过滤。

辅助对象存入现有私有 Storage 体系的 `{userId}/{projectId}/edit-inputs/` 前缀。它与普通资产使用相同项目所有权和签名 URL 规则，不建立公开桶。被 `generation_inputs` 引用的辅助资产随项目保留，以保证重试与审计；未被引用且创建超过 24 小时的辅助资产由定时清理流程删除对象和资产行。

## 三、generation_inputs

新增 `generation_inputs` 表：

| 字段            | 类型          | 约束                                                       |
| --------------- | ------------- | ---------------------------------------------------------- |
| `generation_id` | `uuid`        | 引用 `generations(id) on delete cascade`                   |
| `asset_id`      | `uuid`        | 引用 `assets(id) on delete restrict`                       |
| `role`          | `text`        | `style`、`content`、`first_frame`、`mask`、`keyframe` 之一 |
| `ordinal`       | `smallint`    | 大于等于 0                                                 |
| `created_at`    | `timestamptz` | `not null default now()`                                   |

主键为 `(generation_id, ordinal)`，并建立 `(asset_id)` 和 `(generation_id, role)` 索引。同一 generation 内 `ordinal` 表示请求中的稳定顺序，幂等哈希与 Provider 输入构造都按该顺序消费。

RLS 规则为：项目所有者可通过 generation 所属项目读取输入；浏览器客户端不能直接插入、更新或删除。写入只允许原子提交 RPC 和受内部鉴权保护的 Edge 流程。RPC 在写入前验证每个资产与 generation 属于同一项目且归当前用户所有，防止以资产 ID 跨项目读取。

## 四、操作类型与参数存储

旧 generation 继续保留 `operation_type = 'generation'`。新图片编辑分别写入：

- `image:semantic_edit`
- `image:inpaint`
- `image:outpaint`
- `image:remove_background`
- `image:upscale`

完整判别联合仍存入 `generations.params` JSONB；`generation_inputs` 是经过所有权验证后的结构化输入索引，不替代参数快照。普通图片生成带参考图时，新客户端使用 `semantic_edit`；旧客户端缺少 operation 时由服务端根据请求形状规范化，但数据库旧记录不回填。

## 五、原子提交

为现有 `create_generation_submission` 增加兼容的新签名或版本化 RPC。单一事务执行：

1. 验证用户、项目、会话、目标节点和模型目录权限。
2. 规范化图片操作并计算包含操作、参数、模型、目标节点和有序输入资产的请求哈希。
3. 在用户与项目作用域内检查幂等键；相同哈希返回既有 generation，不同哈希返回 `idempotency_conflict`。
4. 插入 generation，记录 `operation_type`、目标节点和 `candidate_for_target` 结果模式。
5. 验证并插入全部 `generation_inputs`。
6. 创建一个 generation 占位；多候选由完成阶段按已归一化结果数量补充，不预建无法对应结果的空节点。
7. 提交事务并返回 generation、占位节点和幂等结果。

任一步失败全部回滚。调用外部 Provider 只能发生在事务提交后，避免持锁等待网络；外部提交失败通过 generation 状态落库，不删除已经建立的可重试输入血缘。

## 六、幂等与并发

请求哈希必须包含：规范化 operation、prompt、模型键、目标节点 ID、结果模式、完整操作参数，以及按 `ordinal` 排序的 `{assetId, role}`。不包含客户端生成的临时对象 URL、覆盖层状态、占位节点视觉坐标之外的瞬态数据。

Webhook 与轮询进入同一完成事务，通过 generation 行锁和终态检查保证只落地一次。多个候选以 Provider 归一化后的顺序创建；已存在相同结果指纹时不重复创建资产或候选节点。重试生成新的 generation 和幂等键，但复制原 generation 的输入引用，不重新渲染或上传蒙版。

## 七、候选采用事务

候选采用 RPC 新增 `geometry_mode`：

- `preserve_frame`：交换主节点和候选节点的资产引用、媒体元数据与编辑来源元数据，两个节点的位置、宽高、旋转和父级保持原值。
- `adopt_output_geometry`：在交换内容的同时交换双方的 `x`、`y`、`width`、`height`，并校正主节点使其中心等于采用前主节点中心；旋转和父级仍归主节点所有。

RPC 锁定主节点、候选节点和对应候选边，验证二者同项目、当前用户拥有、边类型为 `media_candidate` 且候选确实属于目标。事务完成后主节点 ID 不变，候选边仍指向现在承载旧内容的节点。扩图必须使用 `adopt_output_geometry`，其他操作必须使用 `preserve_frame`；服务端根据 generation operation 再次验证，不能仅相信客户端参数。

## 八、生命周期与兼容

- 迁移只新增字段、表、索引、策略和兼容 RPC，不删除旧函数或更改既有字段含义。
- `is_auxiliary` 默认 `false`，历史资产无需回填。
- 历史 generation 没有 `generation_inputs` 仍可读取和展示；只有新编辑请求要求结构化输入。
- 删除项目时按既有项目级级联和 Storage 清理删除 generation 输入与辅助资产。
- 删除单个被 generation 引用的资产必须被外键拒绝；项目生命周期清理由服务端按引用顺序执行。
- Realtime 发布继续以 generation、canvas_nodes、canvas_edges 和 assets 为主；`generation_inputs` 不向浏览器实时广播。

## 九、失败处理

- 资产不属于项目、蒙版缺失、输入数量错误或 operation 不匹配时返回 `invalid_params`，`details.reason` 使用稳定原因字面量。
- 模型或适配器不支持 operation 时返回 `unsupported_param`，原因使用 `unsupported_image_operation`。
- 幂等键对应不同请求时返回 `idempotency_conflict`，不覆盖原任务。
- 候选已被删除、已不属于目标或任务不是终态成功时返回 `conflict`。
- 辅助对象已上传但 RPC 回滚时，由客户端立即清理；未清理成功的孤儿由 24 小时任务回收。
- 数据库迁移回滚不删除已经写入的输入血缘；生产回滚通过停用入口和能力完成。

## 十、验收

- pgTAP 验证所有表约束、索引、RLS、跨项目攻击和只读客户端策略。
- 原子提交在 generation、输入或占位任一插入失败时不留下部分数据。
- 相同幂等请求并发提交只返回一个 generation 和一组 inputs。
- Webhook、轮询并发完成只创建一组结果资产和候选节点。
- 两种候选几何模式均保持主节点 ID，扩图中心点和宽高比计算可重复。
- 旧生成、旧资产查询和历史项目在迁移后行为不变。
