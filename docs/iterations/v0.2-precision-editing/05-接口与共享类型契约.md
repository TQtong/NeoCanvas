# v0.2.0 接口与共享类型契约

## 一、目标

以根目录 `types/` 为唯一共享类型源，定义前端、Edge Function、适配器和数据库共同消费的图片操作、参数、能力与错误详情。Edge 侧生成契约必须由根类型同步，手写副本不得成为第二真相源。

## 二、图片操作

```ts
type ImageOperation =
  | 'generate'
  | 'semantic_edit'
  | 'inpaint'
  | 'outpaint'
  | 'remove_background'
  | 'upscale';
```

`generate` 表示无必需源图片的普通图片生成；其余五项表示 v0.2.0 编辑。数据库 `operation_type` 使用带模态前缀的值，除旧值 `generation` 外不得直接存储上述裸字面量。

## 三、图片参数判别联合

所有新分支共享现有 `modality: 'image'`、质量、种子、宽高等通用字段，并由 `operation` 判别：

| operation           | 必需字段                                                             | 可选字段                                    | 数量约束             |
| ------------------- | -------------------------------------------------------------------- | ------------------------------------------- | -------------------- |
| `generate`          | `references`、`count`                                                | 现有生成参数                                | 按模型 `maxOutputs`  |
| `semantic_edit`     | `inputMode`、至少一个 `content` 引用、`count`                        | `style` 引用、`inputFidelity`、`background` | 1–4 且不超过模型上限 |
| `inpaint`           | `inputMode`、一个 `content`、一个 `mask`、`maskFeatherPx`、`count`   | `inputFidelity`、`background`               | 1–4 且不超过模型上限 |
| `outpaint`          | `inputMode`、一个 `content`、`outputCanvas`、`count`                 | `inputFidelity`、`background`               | 1–4 且不超过模型上限 |
| `remove_background` | `inputMode`、一个 `content`、`background: 'transparent'`、`count: 1` | 无                                          | 恰好 1               |
| `upscale`           | `inputMode`、一个 `content`、`upscaleFactor`、`count: 1`             | 无                                          | 恰好 1               |

`inputMode` 固定为 `'original' | 'flattened'`；`inputFidelity` 固定为 `'standard' | 'high'`；`background` 固定为 `'transparent' | 'opaque' | 'auto'`；`upscaleFactor` 固定为 `2 | 4`；`maskFeatherPx` 为 `0–128` 的整数。

`OutputCanvas` 结构为：

```ts
interface OutputCanvas {
  width: number;
  height: number;
  sourceX: number;
  sourceY: number;
  sourceWidth: number;
  sourceHeight: number;
}
```

六个值均为正整数，只有 `sourceX` 和 `sourceY` 可以为零；源矩形必须完全位于输出画布内，且 `sourceWidth`、`sourceHeight` 等于本次提交输入的像素尺寸。

`ReferenceMaterial.role` 沿用 `style | content | first_frame | mask | keyframe`。图片编辑源图使用 `content`，局部重绘蒙版使用 `mask`；不增加功能重复的 `source` 或 `flattened_source` 角色，是否为合成输入由 `inputMode` 与资产的 `is_auxiliary` 表达。

## 四、旧请求规范化

为避免破坏现有客户端，图片参数采用「新判别联合 + 旧形状兼容入口」：

- 没有 `operation` 且没有图片引用时规范化为 `generate`。
- 没有 `operation` 且存在 `content` 或 `style` 图片引用时规范化为 `semantic_edit`，`inputMode` 取 `original`。
- 缺少 operation 的旧请求不能携带 `mask`、扩图画布、放大倍数或透明背景专属字段；出现时返回 `invalid_params`。
- 规范化发生在参数校验和幂等哈希之前，使等价新旧请求获得稳定语义。
- 服务端响应始终返回规范化后的 operation；数据库历史行不批量回填。

## 五、模型能力

`ModelCapabilities` 增加：

```ts
interface ImageOperationCapabilities {
  imageOperations: ImageOperation[];
  maxInputImages?: number;
  inputFidelityOptions?: Array<'standard' | 'high'>;
  upscaleFactors?: Array<2 | 4>;
  supportsTransparentOutput?: boolean;
  maxInputPixels?: number;
}
```

- `imageOperations` 对图片模型必填；迁移后的旧图片模型至少显式包含 `generate` 或其唯一工具操作。
- `maxInputImages` 统计非蒙版图片；蒙版仍受 operation 的恰好一个约束。
- `inputFidelityOptions` 缺省表示不支持该参数；客户端不得发送隐藏默认值。
- `upscaleFactors` 只对 `upscale` 有效，必须是 `2`、`4` 的非空子集。
- `supportsTransparentOutput` 为 `true` 才能发送透明背景或开放去背景。
- `maxInputPixels` 是经过预处理后传给 Provider 的总像素上限；同时还要满足模型既有宽高限制。
- 首页和普通聊天生成模型查询必须过滤 `imageOperations` 包含 `generate`，工具型目录项不得出现。

## 六、生成提交与响应

继续复用 `submit-generation` 的统一请求，不新增平行图片编辑端点。新图片编辑请求必须提供：

- `modality: 'image'`
- operation 判别后的 `params`
- `targetNodeId`
- `resultMode: 'candidate_for_target'`
- 稳定 `idempotencyKey`
- 候选占位所需 `placement`

提交成功响应包含 generation、首个占位节点、规范化 operation 和 `deduplicated` 标识。幂等命中返回同一 generation，不重复上传输入或创建占位。客户端在辅助资产上传完成后才调用提交，服务端通过 `generation_inputs` 固化最终输入。

重试接口接收失败 generation ID、新幂等键和可选新模型键。默认复制原 prompt、规范化参数、目标节点和有序输入引用；更换模型后必须重新校验 operation 和尺寸，但不重新渲染源图或蒙版。

候选采用请求包含主节点 ID、候选节点 ID 和 `geometryMode`。服务端依据候选 generation operation 校验几何模式：扩图只能使用 `adopt_output_geometry`，其他编辑只能使用 `preserve_frame`。

## 七、Realtime 契约

不新增 `generation_inputs` 浏览器订阅。客户端继续订阅：

- generation 状态、进度、错误和结果元数据；
- 占位与结果 `canvas_nodes`；
- `media_candidate` 边；
- 采用候选导致的主/候选节点更新。

Realtime 回声抑制按节点和 generation ID 工作。候选采用事务产生的多行变化必须在客户端聚合为一次内容交换，避免中间帧同时显示两份相同内容；事件乱序时以数据库重新拉取的主节点和候选边快照校正。

## 八、错误契约

不新增另一套图片编辑错误码。继续使用 `types/api.ts` 中的小写 `ErrorCode`，并用 `details.reason` 提供稳定分支：

| ErrorCode           | `details.reason`                 | 场景                               |
| ------------------- | -------------------------------- | ---------------------------------- |
| `unsupported_param` | `unsupported_image_operation`    | 模型、适配器或自定义协议不支持操作 |
| `invalid_params`    | `invalid_edit_input_count`       | 源图、蒙版或候选数量错误           |
| `invalid_params`    | `empty_mask`                     | 局部重绘蒙版没有可编辑像素         |
| `invalid_params`    | `output_canvas_invalid`          | 扩图画布无法完整容纳源图           |
| `unsupported_param` | `input_pixels_exceeded`          | 输入或输出超过模型能力             |
| `unsupported_param` | `upscale_factor_unsupported`     | 模型不支持请求倍数                 |
| `unsupported_param` | `transparent_output_unsupported` | 模型不支持透明输出                 |
| `not_found`         | `edit_target_missing`            | 目标图片、输入资产或候选不存在     |
| `conflict`          | `edit_target_changed`            | 候选关系或目标状态不再满足采用条件 |
| `provider_error`    | `provider_result_invalid`        | Provider 没有返回可验证媒体        |

错误 `message` 按语言本地化，`details` 不包含密钥、签名 URL、图片内容或 Provider 原始敏感响应。HTTP 状态继续由现有 `ERROR_HTTP_STATUS` 映射决定。

## 九、兼容与版本演进

- 新字段先在共享根类型添加，再生成 Edge 契约并运行漂移检查。
- 模型能力数据和服务端适配器先发布，前端入口最后启用。
- 旧客户端继续提交无 operation 参数，服务端在至少一个完整发布周期内保持规范化支持。
- 新客户端遇到旧服务端缺少能力字段时隐藏精准编辑入口，不假定模型支持。
- 不修改视频、文本生成和现有 `GenerationResultMode` 字面量。

## 十、验收

- 根类型与 Edge 生成类型逐字一致，契约检查没有手写漂移。
- 每个 operation 都有合法与非法参数的运行时校验测试。
- 旧图片生成和旧参考图请求可按规定规范化，新专属字段不会被旧分支接受。
- 模型能力能够独立表达工具型模型、透明输出、输入上限和放大倍数。
- 提交、重试、候选采用及 Realtime 不引入第二套响应封套或错误码。
