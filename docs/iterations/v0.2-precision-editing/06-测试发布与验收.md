# v0.2.0 测试发布与验收

## 一、目标

用可重复的自动化测试和受控真实 Provider 冒烟证明精准编辑链路不会破坏原图、不会绕过能力校验、不会重复落地结果，并能在失败或回滚时保持现有生成和画布能力可用。

## 二、测试数据与环境

- 单元和端到端测试使用仓库内固定图片、透明 PNG、裁剪参数、滤镜参数、蒙版笔画和字体资源。
- Playwright 使用确定性测试 Provider，按请求 operation 返回固定图片和元数据，不依赖外部 API 波动。
- Deno 适配器测试拦截网络请求，只验证 endpoint、headers、body、签名、字段映射和响应归一化。
- pgTAP 在独立测试项目数据中执行，至少包含两个用户和两个项目，用于验证跨项目 RLS。
- 真实 Provider 冒烟只在受控 staging 运行，使用专用低额度凭据和不含敏感信息的测试图片。

## 三、单元与组件测试

### 能力与参数

- 六种 `ImageOperation` 的合法判别与非法字段组合。
- 模型目录、适配器、凭据三者能力交集；自定义 Provider 只能收窄能力。
- 普通生成入口排除没有 `generate` 的工具模型。
- 编辑输入数量、蒙版唯一性、候选数、透明输出、像素上限和放大倍数。
- 旧请求到 `generate`/`semantic_edit` 的规范化及等价幂等哈希。

### 坐标与渲染

- 裁剪、非整数预览缩放、DPR 1/1.5/2 和预览留白下的指针到源像素转换。
- 画笔、橡皮、清空、200 条历史压平、撤销重做和 `0–128` 羽化结果。
- 扩图四边拖动、七种比例预设、中心锚定、源矩形包含和模型上限。
- 合并当前外观覆盖图片、文本、形状、手绘、滤镜、层级、透明像素及组外排除。
- 放大结果只改变资产自然尺寸，`preserve_frame` 不改变节点外框。

### 编辑器组件

- 打开和关闭时的 React Flow 锁定/解锁、视口保持和焦点恢复。
- 操作切换时清除不适用参数，模型切换时按能力重置参数。
- 上传、提交、生成失败后保留正确状态；取消不产生写入。
- 中英文文案、可访问名称、键盘快捷键和透明棋盘格。

## 四、Provider 契约测试

| Provider        | 必测内容                                                       |
| --------------- | -------------------------------------------------------------- |
| OpenAI          | 源图数组与单独 `mask` 字段、输入保真度、透明输出、扩图输入布局 |
| Google          | 语义编辑图片 Part 顺序、无图片结果失败、拒绝蒙版操作           |
| Ark             | 生成与 SeedEdit 模型能力分离、图片字段与结果解析               |
| Jimeng          | 每个 action 的签名、版本、字段映射、权限失败和结果路径         |
| MiniMax         | `subject_reference` 人物映射，拒绝蒙版、扩图和放大参数         |
| SiliconFlow     | Qwen Image Edit 仅开放已验证语义编辑，其他模型保持普通生成     |
| fal.ai          | `image_url`/`mask_url`、白编黑保语义、透明 Alpha、Topaz 2×/4×  |
| Replicate       | 固定版本 Profile、各类输出形状归一化、未知 Profile 拒绝        |
| 自定义 Provider | 能力交集、endpoint 继承、无法伪造适配器未支持操作              |

每个开放操作至少包含成功响应、Provider 4xx、Provider 5xx、超时、空结果、无效 MIME 和结果数量不符测试。每个未开放操作至少包含一条服务端拒绝测试，且验证没有发起外部网络请求。

## 五、数据库与并发测试

pgTAP 必须覆盖：

- `assets.is_auxiliary` 默认值、索引与普通素材过滤。
- `generation_inputs` 主键、角色约束、外键、顺序、同项目验证和 RLS。
- 普通用户不能直接写入 input，项目所有者可以读取自己的记录且不能跨项目读取。
- 原子提交在 generation、input 或占位插入失败时完全回滚。
- `operation_type` 与规范化 operation 一致。
- 两种候选采用策略、主节点 ID、候选边、中心点和宽高比。
- 历史 generation 无输入记录时仍能读取，历史资产默认非辅助。

并发测试必须覆盖：

- 20 个相同幂等请求只创建一个 generation、一组 inputs 和一个首占位。
- 相同幂等键不同哈希稳定返回 `idempotency_conflict`。
- Webhook 与轮询同时完成只落地一次结果。
- 两个采用请求竞争同一候选只有一个成功，失败方得到 `conflict`。
- 重试复制同一组有序输入，不创建重复辅助资产。

## 六、Playwright 端到端

使用确定性 Provider 执行以下独立场景：

1. 上传固定图片，进入语义编辑，生成两个候选，确认原图未变，采用第二候选并验证主节点 ID 不变。
2. 绘制、擦除、羽化和撤销蒙版，提交局部重绘，验证上传蒙版尺寸及白编黑保语义。
3. 选择 `16:9` 扩图并拖动一侧，生成候选，采用后验证中心不变和新宽高比，旧内容保留为候选。
4. 去背景结果以棋盘格显示，下载的测试资产含 Alpha，采用后节点外框不变。
5. 2× 与 4× 放大分别更新自然像素，节点 flow 宽高不变。
6. 切换「合并当前外观」，验证裁剪、滤镜和同组叠加进入辅助输入，组外节点不进入。
7. 无可用 Provider 时显示禁用说明和配置入口；构造越权请求时服务端返回 `unsupported_param`。
8. 模拟源图加载、字体、上传、提交、Provider、结果下载失败，验证会话恢复和原图不变。
9. 编辑期间接收目标节点删除和更新 Realtime，验证删除禁止提交、更新保持冻结输入并提示。
10. 键盘完成打开、绘制、撤销、提交和退出，焦点回到原工具栏按钮。

## 七、性能与资源测试

- 在 100、500、1000 节点基准项目中记录打开/关闭编辑器前后的节点挂载数、视口和交互耗时，不允许因编辑器切换全量重建画布。
- 连续绘制 500 条笔画，验证历史压平后内存趋于稳定、最近 200 条仍可撤销。
- 分别测试高分辨率源图、透明图、复杂同组叠加和达到模型像素上限的扩图。
- 使用浏览器性能记录验证画笔移动不触发节点列表或聊天列表重渲染。
- 成功、取消、上传失败和组件卸载后检查对象 URL、Bitmap、异步任务和 Pointer Capture 均已释放。
- 性能验收以同一测试机现有 100/500/1000 节点基线为参照：非编辑状态不得退化超过 10%，编辑器打开后画笔交互不得出现连续 100 毫秒以上的主线程阻塞。

## 八、真实 Provider 冒烟

每个准备启用的 operation/model 组合至少执行：

- 一次最小合法成功请求，验证结果可转存自有 Storage、尺寸和 MIME 正确。
- 一次能力或参数错误，验证统一错误映射且不泄露外部响应敏感信息。
- 异步 Provider 额外执行一次轮询完成；支持 Webhook 的 Provider 再验证签名和重复回调。

某个组合失败时只把该模型的对应 operation 从能力目录移除。普通生成能力和其他 Provider 不受影响。真实测试证据记录 generation ID、模型目录版本、结果状态和日志查询位置，不在文档或 CI 输出中记录密钥与签名 URL。

## 九、发布、监控与回滚

发布顺序固定为：

1. 应用增量数据库迁移、RLS、索引和兼容 RPC。
2. 部署支持新契约但仍兼容旧请求的 Edge Functions。
3. 更新模型目录；编辑 operation 初始保持关闭。
4. 部署带 `NEXT_PUBLIC_IMAGE_EDITING_ENABLED=false` 的前端。
5. 在 staging 完成真实 Provider 冒烟，逐个开启通过验证的模型 operation。
6. 打开内部用户前端开关，观察完整监控窗口后再全量开启。

监控按 operation/provider/model 汇总成功率、P50/P95 耗时、超时率、无效结果率、辅助资产上传失败率、输入输出像素、候选数量和采用率。生成终态与采用动作使用 `neocanvas.generation.v1` 的 `generation_succeeded`、`generation_failed`、`candidate_adopted` 结构化事件；只记录原子事务胜者。候选采用率以采用事件数除以候选模式成功事件的 `outputCount`，重复交换视为新的主动采用行为。稳定错误码随失败事件记录，日志不包含提示词、引用、临时地址或 Provider 原始响应。告警使用现有日志与数据库可观测链路，不为本版本引入新的外部监控依赖。

回滚时先关闭 `NEXT_PUBLIC_IMAGE_EDITING_ENABLED`，再停用模型目录中的编辑 operation，最后按需回滚 Edge 流量。数据库迁移保持原位，输入血缘和辅助资产不删除；旧客户端和普通生成继续运行。

## 十、最终门禁与验收

合并与发布前必须全部通过：

- `npm run typecheck`
- `npm run lint`
- 共享契约漂移检查
- Vitest 单元与组件测试
- Deno check 与适配器测试
- pgTAP 数据库测试
- 幂等、Webhook/轮询和候选采用并发测试
- Playwright 十类端到端场景
- 100/500/1000 节点性能与资源测试
- 所有拟启用 Provider 的成功、错误真实冒烟

版本验收完成的定义是：五类操作均能从图片节点进入；所有结果非破坏地进入候选分支；精准蒙版只由真实支持的模型执行；失败和重试不改变原节点；Realtime 与候选采用没有重复落地；关闭功能开关即可安全停止入口。
