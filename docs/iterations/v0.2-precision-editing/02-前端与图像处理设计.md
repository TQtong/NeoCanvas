# v0.2.0 前端与图像处理设计

## 一、目标

在现有设计页和三库架构之内增加专业图片编辑能力，保证画布实例、视口和数据库投影稳定。所有交互中的笔画和临时图像属于一次局部会话，只有生成提交成功后才进入现有 generation 与 Realtime 数据流。

## 二、组件边界

编辑功能按以下职责拆分：

- `ImageEditOverlay`：管理专注模式、焦点陷阱、退出确认和画布交互锁定。
- `ImageEditStage`：显示源图、透明棋盘格、蒙版层和扩图边框，负责预览坐标转换。
- `MaskEditor`：采集画笔与橡皮笔画、渲染遮罩、执行局部撤销重做。
- `OutpaintFrame`：处理四边拖动、比例预设、中心锚定和尺寸限制。
- `ImageEditControls`：操作、输入来源、模型、提示词、候选数量、羽化与放大倍数。
- `useImageEditSession`：保存一次编辑的不可变快照、状态机、参数、笔画栈和异步取消信号。
- `image-edit-renderer`：无 UI 的源图解析、合成、蒙版栅格化、扩图准备和降采样模块。

不新增全局 Zustand 库。编辑会话由设计工作台中的局部 Hook 持有；只有提交后创建的 generation、占位节点和 Realtime 结果进入现有画布库与对话库。

## 三、生命周期与数据流

1. 工具栏把 `projectId`、目标节点 ID 和触发按钮引用交给 `ImageEditOverlay`。
2. Hook 在打开瞬间冻结目标节点、同组节点、资产元数据和当前输入模式所需的外观快照。
3. Storage 层续签源资产 URL，解码图片并读取真实自然尺寸；后续画布 Realtime 更新不替换本次冻结快照。
4. 用户编辑期间，笔画、扩图框和提示词只更新局部 reducer；React Flow 保持挂载但禁止拖拽、连线、缩放、框选和删除。
5. 提交时渲染器按冻结快照生成所需 Blob，经 Storage 封装上传为辅助资产，再调用统一生成提交。
6. 原子提交成功后清除本地 Blob 和对象 URL、关闭覆盖层，画布使用既有占位与 Realtime 流程。
7. 准备、上传或提交失败时回到编辑态；只有确认取消或提交成功才销毁会话。

关闭期间收到目标节点被删除的 Realtime 事件时，编辑器进入只读错误态，禁止提交并允许退出；目标节点仅发生外观更新时不改写已冻结输入，同时提示「画布内容已在其他位置更新，本次仍使用打开编辑器时的版本」。

## 四、坐标系

图片编辑使用三套显式坐标：

- **源像素坐标**：以编辑输入左上角为 `(0, 0)`，保存笔画点、画笔宽度和羽化值。
- **预览坐标**：编辑器内经等比缩放和居中后的 CSS 像素，用于 Pointer Event 命中。
- **输出画布坐标**：扩图后的目标像素平面，用 `outputCanvas` 描述源图片在其中的位置。

预览点到源像素的转换先扣除预览图偏移，再除以显示比例，并钳制到源图范围。蒙版 Canvas 的逻辑宽高等于源输入像素，渲染后再以 CSS 尺寸缩放；设备像素比只影响预览清晰度，不改变保存坐标。Pointer Event 使用捕获保证移出编辑区后仍能正确结束一条笔画。

扩图结构固定为：

```ts
interface OutputCanvas {
  width: number;
  height: number;
  sourceX: number;
  sourceY: number;
  sourceWidth: number;
  sourceHeight: number;
}
```

`sourceX`、`sourceY` 不得为负，源图矩形必须完全位于输出画布内。比例预设以源图中心为锚点生成能完整容纳源图的最小画布；自由拖动只扩大四边。提交前按模型像素和边长限制进行验证。

## 五、高保真输入渲染

统一渲染器替代目前只服务视频帧的简单合成路径，并由图片编辑和视频输入共同复用。渲染顺序为：

1. 解码源资产，依据节点 `crop` 计算源矩形。
2. 把裁剪内容绘制到合成基准画布，应用亮度、对比度、饱和度、模糊等现有滤镜。
3. 当输入模式为 `flattened` 时，收集相同 `groupId` 且可见的支持节点，按绝对 z-index 排序。
4. 将叠加节点从 flow 坐标转换为相对选中图片内容框坐标，按现有节点渲染语义绘制并裁切到基准范围。
5. 输出带正确 MIME 和像素元数据的 PNG Blob；没有透明像素且 Provider 更适合 JPEG 时仍保留 PNG 作为可复现辅助输入，由适配器决定传输格式。

不参与合成的对象包括边、控件、选择框、画板背景、候选面板、生成占位和不可见节点。节点旋转、外框透明度和 React Flow 视口不烧录。字体未加载成功时阻止合成并提示重试，禁止悄悄使用替代字体。

## 六、蒙版渲染

笔画记录为 `{ tool, points, sizePx }`，点包含源像素 `x`、`y` 和压力值；没有压力设备时压力固定为 `1`。重放全部有效笔画到离屏 Canvas：画笔使用白色 `source-over`，橡皮使用黑色覆盖。清空操作以历史游标表示，不复制整张位图。

羽化在最终输出阶段处理，对二值蒙版边缘执行半径为 `maskFeatherPx` 的确定性模糊，再把中心区域恢复为纯白、外部恢复为纯黑。输出为与编辑输入同宽高的 PNG；如果 Provider 要求 Alpha 蒙版，由适配器负责通道转换，前端标准资产始终保持黑底白区语义。

蒙版历史最多保留 200 条笔画；超过后将最早一段压平为基础位图并继续保留最近 200 条可撤销笔画，避免无限增长。压平不改变最终像素结果。

## 七、尺寸、内存与资源管理

- 首次解码优先使用 `createImageBitmap`；不可用时回退 HTMLImageElement，错误统一返回可识别阶段。
- 同一时刻只保留源图、预览图、蒙版和一个待上传输出；完成每一步立即释放临时 Canvas、Bitmap 和对象 URL。
- Provider 提交输入依据 `ModelCapabilities.maxInputPixels` 与其边长要求生成降采样辅助副本；原始资产永不覆盖。
- 降采样保持宽高比，使用高质量多阶段缩放；蒙版以相同变换同步缩放，最后阈值和羽化重新计算，防止边界错位。
- 放大操作直接提交原始最高分辨率资产，不先降为节点预览尺寸。
- 用户切换模型导致上限改变时重新验证，但在再次提交前不重复上传辅助资产。

## 八、模型能力过滤

客户端可见模型满足以下全部条件：模型处于启用状态、模态为图片、`imageOperations` 包含当前操作、对应 Provider 凭据可用、适配器协议声明支持当前操作。普通聊天和主页生成入口额外要求包含 `generate`。

过滤只用于用户体验，不是安全边界。提交时 Edge Function 必须重新读取目录和凭据执行同样交集校验。模型切换后，不被新模型支持的 `inputFidelity`、候选数或放大倍数立即恢复为该模型默认值，并在界面显示变化原因。

## 九、失败处理

- 每次打开编辑器创建独立 `AbortController`；取消只终止本地解码、合成和尚未完成的上传，不取消已原子提交的 generation。
- 关闭编辑器前检查本地会话是否偏离初始状态；有改动时显示确认框。
- 辅助资产部分上传失败时，删除本次会话创建且尚未被 generation 引用的对象和资产行；若删除失败，标记为辅助资产并交由生命周期清理。
- 浏览器 Canvas 污染、解码失败、内存不足和字体缺失分别记录阶段，不用空白图片继续提交。
- React Flow 锁定必须在覆盖层卸载的 `finally` 中解除，错误边界也不得让画布永久不可操作。

## 十、性能与验收

- 100、500、1000 节点场景打开编辑器时 React Flow 不卸载，视口矩阵和当前选择保持逐值一致。
- 画笔移动只重绘蒙版覆盖层，不触发画布节点列表或右侧聊天消息列表重渲染。
- 坐标测试覆盖裁剪、非整数缩放、DPR 1/1.5/2、预览留白和边界钳制。
- 合成快照测试覆盖图片、文本、形状、手绘、滤镜、层级、组外排除和透明像素。
- 所有成功路径释放 Bitmap、临时 Canvas 引用和对象 URL；取消、异常和组件卸载路径得到同样验证。
- 编辑器具备焦点恢复、完整键盘操作和中英文可访问名称。
