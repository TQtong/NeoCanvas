# 项目总览与文档导航

## 一、项目定位

本项目的产品名为 **NeoCanvas**，是一款以「对话驱动 + 无限画布」为核心范式的 AI 设计代理（AI Design Agent）产品，目标是让非专业用户与专业设计师都能通过自然语言指挥多模态生成模型，在一块可无限平移、缩放的画布上完成图像、视频与图文内容的创作、编排与迭代。产品的口号是「让设计更简单」，其本质是把「图像 / 视频生成模型」「设计编辑画布」「智能体编排」三者融合为一个连续的创作工作流：用户在主页输入一句想法并选择模型，系统即为其创建一个项目并进入设计页；在设计页中，左侧是承载一切视觉元素的无限画布，右侧是与智能体对话的面板，用户通过持续对话让画布上的内容生长、变形、组合，直至得到满意的成品。

产品形态对标 Lovart 一类的「设计代理」工具。它不是传统的、以图层面板为中心的图形编辑器，也不是单纯的「文生图」站点，而是一个**以智能体为中枢、以画布为舞台、以多模型为画笔**的创作系统。这一定位决定了三条贯穿全套文档的主线：画布必须是真正的无限画布（基于 React Flow / xyflow 构建），后端必须以 Supabase 作为统一的数据、鉴权、存储、实时与边缘计算底座，而前端必须以 Next.js 承载主页与设计页两个核心界面。

## 二、范围边界

本套文档严格限定在需求方给出的两张界面草图所确立的功能范围之内，不引入任何草图之外的页面或区域。

主页（对应第一张草图）只包含三个区块：顶部居中的产品标识与标语、其下的对话输入框与模型选择条、页面下半部分的「最近项目」区。模型选择条包含 GPT Image 2、Seedance 2.0、Nano Banana Pro 三个具体模型入口，以及 Design、Branding、E-Commerce、Video 四个创作场景入口。右上角包含用户头像。「最近项目」区由一张「新建项目」卡片与若干历史项目缩略图卡片组成，每张历史卡片显示项目名与更新时间。

设计页（对应第二张草图）只包含两个区域：占据主体的左侧无限画布，与停靠在右侧的对话面板。除此之外不增加任何其他面板。画布底部居中悬浮一条工具栏，画布左下角是缩放与图层等少量控件，顶部左侧是项目名与重命名入口，顶部右侧是头像与面板的展开 / 分享 / 收起控制。右侧对话面板顶部是「新对话」标题，主体是引导语「What do you want to create?」与对话输入框，输入框支持 `@` 提及画布元素、附件上传与 Agent 模式切换。

凡是草图未出现的能力——例如多人协作光标、评论批注、素材市场、社区广场、复杂的图层树编辑器——均不在本期实现范围内。文档在涉及这些方向时仅以「可扩展点」一笔带过，不展开设计，以确保交付聚焦。

## 三、技术选型总览

前端框架选用 Next.js（App Router 形态）。选择它的核心理由有三：其一，React 生态是 React Flow 的唯一一等公民运行环境，画布与框架天然同源；其二，App Router 的服务端组件（RSC）能让主页的项目列表、用户信息等数据在服务端直出，首屏快且对 SEO 友好，而设计页的画布则可作为客户端组件独立运行；其三，Next.js 与 Vercel、与 Supabase 的集成生态成熟，鉴权中间件、流式响应、边缘渲染都有现成范式。

无限画布引擎选用 xyflow 的 React Flow（npm 包名 `@xyflow/react`，MIT 许可）。React Flow 原生提供了无限平移与缩放的视口（viewport）、点状 / 线状背景网格、缩放控件、自定义节点类型、节点缩放手柄（NodeResizer）、节点浮动工具条（NodeToolbar）、仅渲染可视区域节点的性能优化等能力。本项目把画布上的每一个视觉元素（图片、文本、形状、手绘、视频、生成占位）都建模为 React Flow 的一个自定义节点，从而以最小的自研成本获得一个工业级的无限画布底座。

后端底座选用 Supabase。它以 PostgreSQL 为核心，向上提供 Auth（基于 GoTrue 的 JWT 鉴权，支持邮箱、魔法链接与 OAuth）、自动生成的 RESTful 数据接口（PostgREST）、Storage（基于 S3、支持图片变换与签名 URL 的对象存储）、Realtime（基于 Elixir 的实时服务，可订阅数据库行变更、广播消息、同步在线状态）、Edge Functions（Deno 运行时的全球分布式无服务器函数）、以及 pg_cron 定时任务、Database Webhooks、Supabase Queues 持久消息队列等数据库原生能力。这些能力恰好覆盖了本项目所需的全部后端面：用户体系、项目与画布数据的持久化、生成产物的存储、生成状态的实时推送、调用外部模型 API 的服务端代理、以及异步生成任务的排队与轮询。选择 Supabase 而非自建后端，可以让团队把精力集中在画布交互与生成编排这两处真正的产品差异点上。

多模态生成能力通过统一的「模型适配器（Model Adapter）」抽象层接入。底层对接 OpenAI（GPT Image 2，图像）、Google（Nano Banana Pro，图像）、火山方舟 Volcengine Ark（Seedance 2.0 视频与 Seedream 图像），并预留 fal.ai、Replicate 等聚合平台适配器位置。适配器对上层暴露统一的提交、查询、归一化结果三组语义，使得「新增一个模型」退化为「实现一个适配器 + 在模型目录表中追加一行」。

## 四、文档体系导航

本套设计共七份文档，按「总览 → 需求 → 架构 → 数据 → 前端 → AI → 接口」的认知顺序组织，彼此正交、互不重复。阅读建议是先读本文与需求设计建立全局认知，再依据角色选择深入：前端工程师重点读架构设计、前端开发设计与接口契约设计；后端 / 数据工程师重点读数据模型设计、AI 能力设计与接口契约设计；产品与设计负责人重点读需求设计。

第 00 篇《项目总览与文档导航》（本文）确立项目定位、范围边界、技术选型与术语口径，是全套文档的总纲。

第 01 篇《产品需求设计》以两张界面草图为依据，逐区域定义主页与设计页的结构、内容与交互，给出端到端的核心用户旅程、交互细节、视觉设计语言与非功能性需求，并明确范围边界。

第 02 篇《系统架构设计》给出分层架构、前端架构、Supabase 后端架构、AI 服务层架构、实时协同机制、关键数据流、安全架构与部署架构，是连接需求与实现的骨架。

第 03 篇《数据模型与数据库设计》给出 Supabase 上的完整数据模型，包括全部数据表的字段定义、枚举、索引、行级安全（RLS）策略、Storage 存储桶、Realtime 发布配置、数据库函数与触发器，以及数据生命周期。

第 04 篇《前端开发设计》给出 Next.js 工程结构、渲染策略、状态管理方案，并以最大篇幅展开无限画布（React Flow）的工程设计：坐标系、视口管理、自定义节点体系、变换与层级、工具栏状态机、性能策略，以及主页与对话面板的实现要点与工程规范。

第 05 篇《AI 能力与生成服务设计》给出多模型适配器抽象、各提供商适配要点、生成流水线、异步任务处理、智能体编排、内容安全与可观测性。

第 06 篇《接口与契约设计》给出接口风格分层、各 Edge Function 的职责与契约、PostgREST 数据访问约定、Realtime 频道契约、数据库行与画布节点的映射、错误约定、鉴权与幂等。

## 五、术语口径

为避免歧义，全套文档对核心概念采用统一称谓。**节点（Node）**指画布上的一个独立视觉元素，是 React Flow 节点在本产品中的具体化，按内容分为图片、文本、形状、手绘、视频、生成占位等类型。**边（Edge）**指连接两个节点的连线，在本产品中主要用于记录「生成血缘」（某图由某参考图或某节点派生而来）等可选关系，并非画布的主要构件。**画布（Canvas）**指承载全部节点与边的无限二维平面。**视口（Viewport）**指当前屏幕所观察到的画布区域，由平移量与缩放比三个量描述。**项目（Project）**指一块画布及其关联对话的总和，对应主页「最近项目」中的一张卡片。**会话（Conversation）**指一个项目内用户与智能体的连续对话，**消息（Message）**是会话中的一条发言。**生成任务（Generation）**指一次调用外部模型产出图像 / 视频 / 文本的异步作业。**资产（Asset）**指存储在 Storage 中的一份媒体文件（上传或生成而来）。**智能体（Agent）**指右侧对话面板背后负责理解意图、编排生成与画布操作的编排逻辑。**模型目录（Model Catalog）**指驱动模型选择条的可配置模型清单。

## 六、工程约束

本套文档为**前瞻性设计文档**，描述的是「应当如何构建」的技术方向，不含修订记录、缺陷修复记录、回溯性分析或源码块；所有数据结构、接口与库表均以技术叙述与表格表达，待交付实现阶段再落为代码。

实现阶段需遵循的工程标准为：全量 TypeScript 严格模式，禁止任何简化实现、占位符与 TODO；所有公共函数、类型与模块具备完整 JSDoc；关键行内注释采用中文；同一特性涉及的多个文件同时成套交付；命名、目录与代码风格统一由 ESLint 与 Prettier 约束。设计文档本身不展开代码层面的实现细节，但为后续实现预留了清晰、无歧义的技术边界。
