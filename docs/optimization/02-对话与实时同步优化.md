# 对话与实时同步优化

## 目标

恢复设计页“无限画布 + 右侧对话”的完整产品闭环，使项目快照、当前会话、消息、生成状态和画布节点在首次加载、双页面编辑、断线重连与会话切换后保持最终一致。同时为对话面板提供明确的展开、折叠和加载状态，不让布局状态污染数据库业务模型。

## 现状问题

- `app/p/[projectId]/DesignWorkbench.tsx` 只调用 CanvasStore 的水合与重置，未把服务端项目包中的 conversation 和 messages 写入 ChatStore。
- `components/chat/ChatPanel.tsx` 及消息流、输入框、提及选择器、Agent 下拉和附件能力已经存在，但设计工作台没有挂载它们。
- `useRealtimeProject` 仅接收 `projectId`，没有将当前 `conversationId` 传给订阅封装，因此消息 INSERT/UPDATE/DELETE 不会进入 ChatStore。
- generation Realtime 只更新画布状态，没有同步 ChatStore 中与生成任务关联的消息展示状态。
- Realtime 重连后只恢复订阅，不拉取断线窗口内的项目快照；订阅状态也没有转化为用户可见的同步状态。
- 顶栏缺少面板折叠控制；项目重命名成功后依赖旧的服务端 `title` 属性，当前页面不会立即更新。
- 新会话与首次模型选择缺少统一规则，空模型目录、无启用凭据和当前模型失效时的行为不够确定。

本节保留优化前的故障形态；当前实现状态见“实施状态与证据”。

## 实施方案

### 1. 工作台水合与生命周期

`DesignWorkbench` 在首次挂载或 `projectId` 改变时执行单次、成套水合：

1. 将 `bundle.nodes`、`bundle.edges` 和 viewport 写入 CanvasStore。
2. 将 `bundle.conversations`、当前 conversation、该会话 messages 及关联 generations 写入 ChatStore。
3. 从当前会话、项目默认值和可用模型目录计算初始 Agent 与模型选择。
4. 水合完成后再开放输入和持久化，避免初始快照被当作本地编辑写回。
5. 组件卸载或切换项目时，取消订阅、冲洗可安全提交的本地写入并重置两个 Store 的项目态。

水合函数必须幂等。同一项目因 React 严格模式重复执行时，不得重复追加消息或覆盖已有未提交本地编辑。

### 2. ChatPanel 挂载与折叠

设计页采用固定右侧 380px 对话面板，与现有加载骨架保持一致。`DesignWorkbench` 持有 `chatOpen` 这一纯界面状态：

- 默认展开，用户可通过顶栏按钮折叠或恢复。
- 折叠只改变布局和可访问性属性，不卸载 ChatStore、不取消会话 Realtime，也不清空输入草稿。
- 面板宽度变化由 CSS 布局完成，画布在过渡结束后调用 React Flow 的尺寸适配，不改写节点 flow 坐标。
- 顶栏按钮具有 `aria-expanded`、`aria-controls` 和明确中英文案。

项目标题在工作台维护可更新的本地投影。重命名请求成功后立即更新顶栏；请求失败则恢复服务端标题并显示错误。

### 3. 会话与模型选择

当前会话选择遵循确定性顺序：URL 或项目记录明确指定的有效会话优先，其次选择最近更新的未归档会话；均不存在时，调用现有创建会话能力生成一个空会话并设为当前会话。

首次模型选择按以下顺序解析：

1. 当前会话上次使用且仍可用的模型。
2. 项目创建时记录且当前用户可访问的默认模型。
3. `model_catalog` 中已启用、凭据满足要求、按展示顺序最靠前的模型。
4. 没有可用模型时保留输入草稿、禁用提交，并提供进入 Provider 设置的明确入口。

切换会话时保留各会话独立草稿；订阅先建立新会话频道并完成快照加载，再释放旧频道，避免出现无订阅窗口。

### 4. 消息与生成 Realtime

项目订阅扩展为同时处理 `canvas_nodes`、`canvas_edges`、`generations` 与当前会话 `messages`。事件应用规则如下：

- 以数据库行主键去重，INSERT 与 UPDATE 都采用 upsert 语义，DELETE 按主键删除。
- 本客户端已确认的乐观写入使用 mutation id 或实体 revision 抑制回声；不能仅靠固定时间窗口判断回声。
- generation 更新同时投影到 CanvasStore 的占位节点与 ChatStore 的消息附件/状态，两者引用同一 generation id。
- Realtime 事件只携带标识或数据不完整时，从 PostgREST 拉取该实体最新行，不用不完整 payload 覆盖完整状态。
- 非当前会话的消息不加入当前消息列表，但更新 conversation 未读/更新时间摘要。

### 5. 断线重连与快照校正

Realtime 状态统一为 `connecting`、`connected`、`reconnecting`、`disconnected` 和 `error`。发生频道超时、系统错误、浏览器恢复在线或页面从休眠恢复时：

1. 状态切到 `reconnecting`，保留当前画布和输入，不清空界面。
2. 重新获取项目、当前会话、消息、generation、节点、边和 viewport 的权威快照。
3. 先以服务端快照替换已确认投影，再重新叠加尚在 outbox 的本地 mutation。
4. 使用实体 `updated_at`、客户端 revision 与 mutation id 去重，避免旧快照覆盖待提交本地编辑。
5. 快照校正完成后重新订阅，并将状态切为 `connected`；失败时按 1、2、4、8、16、30 秒上限退避。

浏览器 `online` 事件只触发立即重试，不等同于服务端连接已经恢复。连续失败时界面显示“离线，编辑已保存在本机”或“同步失败”，并与画布 `SyncState` 使用同一状态入口。

## 接口变化

建议锁定以下客户端接口：

```ts
type RealtimeStatus = 'connecting' | 'connected' | 'reconnecting' | 'disconnected' | 'error';

function useRealtimeProject(projectId: string, conversationId: string | null): RealtimeStatus;

interface WorkbenchTopBarProps {
  title: string;
  chatOpen: boolean;
  realtimeStatus: RealtimeStatus;
  syncState: SyncState;
  onToggleChat: () => void;
  onTitleChange: (title: string) => void;
}
```

ChatStore 增加 `hydrateProjectChat`、`setCurrentConversation`、`upsertRealtimeMessage`、`removeRealtimeMessage`、`upsertRealtimeGeneration` 和 `reconcileSnapshot`。这些方法必须以实体 id 去重，并与[《画布可靠性与性能优化》](./03-画布可靠性与性能优化.md)定义的 outbox revision 协同。

服务端 HTTP 路径和消息/生成数据库枚举不改变。项目加载包可以增加可选的 `currentConversationId` 与 generation 摘要；旧客户端缺少这些字段时仍按现有数据工作。

## 实施状态与证据（2026-08-25）

- [`DesignWorkbench`](../../app/p/[projectId]/DesignWorkbench.tsx) 以同一项目包水合 CanvasStore 与 ChatStore，并常驻挂载 380px ChatPanel；折叠只改变布局和 `aria-hidden`，不会卸载草稿。
- [`chat-store`](../../stores/chat-store.ts) 已实现项目水合、会话选择、草稿隔离、消息/生成去重和快照校正；生成状态同时投影到画布与对话。
- [`use-realtime-project`](../../lib/hooks/use-realtime-project.ts) 订阅节点、边、消息和生成，公开连接状态，按退避重连，并在首次连接、重连、恢复在线和页面重新可见时读取权威快照。
- 快照读取期间的频道事件会先缓存、后按原序重放，消除了“事件先到、旧快照后到”导致的新节点丢失；该竞态有独立 Vitest，并由双页面 E2E 连续运行验证。
- 顶栏已展示保存与 Realtime 两种独立状态；项目重命名采用乐观更新与失败回滚；无可用模型时保留输入并禁止生成请求。

对应自动化位于 [`tests/unit/chat-store.test.ts`](../../tests/unit/chat-store.test.ts)、[`tests/unit/realtime-project.test.tsx`](../../tests/unit/realtime-project.test.tsx)和 [`tests/e2e/workbench.spec.ts`](../../tests/e2e/workbench.spec.ts)。

## 失败处理

| 场景               | 处理                                                                             |
| ------------------ | -------------------------------------------------------------------------------- |
| 项目快照加载失败   | 保留加载错误页并提供重试，不挂载空白工作台，不创建新会话                         |
| ChatStore 水合失败 | 画布保持只读可见，对话输入禁用，记录项目与会话标识后允许重新水合                 |
| 新会话创建失败     | 继续显示原会话；没有原会话时保留草稿并提示重试                                   |
| 消息提交超时       | 消息保留 `sending` 状态并使用幂等键重试；明确失败后标为 `failed`，不伪装成已送达 |
| Realtime 中断      | 保留本地编辑和草稿，进入退避重连；重连成功必须做快照校正                         |
| 重命名失败         | 恢复最近一次服务端标题并显示可重试错误                                           |
| 无可用模型         | 禁止创建 generation，保留 prompt/附件并引导配置凭据                              |

权限失败、项目不存在和会话不属于项目属于永久错误，不自动无限重试；网络、超时和 5xx 属于暂时错误，遵守退避与次数可观测规则。

## 测试与验收

- 单元测试覆盖工作台双 Store 水合幂等、会话选择、模型回退、消息去重、回声抑制和重连状态机。
- Playwright 验证设计页默认显示 380px 对话面板，折叠后画布正确适配，恢复后草稿和消息仍在。
- Playwright 验证创建新会话、发送消息、刷新页面和切换会话后消息顺序与状态一致。
- 双页面测试在同一项目打开两个浏览器上下文，一侧发送消息或完成生成，另一侧无需刷新即可更新 ChatStore 与 CanvasStore。
- 断线测试在连接中断期间分别产生远端消息和本地节点编辑；恢复后先校正快照再发送 outbox，最终数据库与两个页面一致。
- 项目重命名成功后当前顶栏立即更新，失败时恢复旧标题；重新加载后的标题与数据库一致。
- 无可用模型时提交按钮禁用、草稿不丢失、设置入口可达，且不会向生成接口发请求。
