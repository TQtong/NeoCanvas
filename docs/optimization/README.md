# NeoCanvas 优化与演进文档

## 目标

本目录用于记录 NeoCanvas 从“主链路已可运行”走向“核心链路稳定、可验证、可上线”的实施差距、整改方案与验收标准。这里的文档服务于工程优化，不重新定义产品范围、数据模型或接口语义。

`docs/00-项目总览与文档导航.md` 至 `docs/06-接口与契约设计.md` 仍是产品与架构的唯一设计真相来源。若优化实施需要改变既有设计，必须先修订相应设计真相文档，再同步更新本目录；不能以优化文档单方面覆盖设计约束。

## 现状问题

当前工程已通过 TypeScript 类型检查和生产构建，数据库、RLS、Storage、Realtime、队列及模型适配器的主体结构已经形成，但仍存在以下上线阻断项：

- 设计页未挂载已经实现的对话面板，对话 Store 与消息 Realtime 未完成装配。
- 画布防抖保存可并发执行，失败时会丢失待重试的 upsert；离线恢复、重连校正和签名 URL 续签不完整。
- 生成创建与结果落库的事务边界不足，webhook 与轮询可能重复落库，内部 Edge Function 的调用鉴权需要收紧。
- 根目录共享类型与 Edge Function 类型存在双份维护，格式检查未通过，测试体系尚未建立。
- 千节点场景存在重复请求、全量扫描、逐节点更新与全量快照历史等性能热点。

完整证据和风险分级见[《现状审计与问题清单》](./01-现状审计与问题清单.md)。

以上内容保留为 2026-08-25 优化启动时的审计基线，不代表当前实现状态。整改后的代码、迁移和自动化证据见下方“实施状态”以及各专题文档的同名章节。

## 接口变化

本目录描述的接口变化分为三类：

- 客户端内部接口：Store 水合、同步状态、批量节点更新、Realtime 订阅状态和媒体过期时间。
- Edge Function 与数据库接口：原子创建生成、结果仅落库一次、模型归属校验和内部调用鉴权。
- 工程接口：根 `types/` 到 Edge 契约的生成流程、统一检查命令和 CI 门禁。

对外 HTTP 请求与响应封套保持兼容。需要新增字段时采用可选字段或服务端默认值；数据库采用只前向、非破坏性迁移，不迁移业务数据、Auth 用户、Storage 对象或旧环境配置。

## 失败处理

实施期间的失败按边界处理：

- 客户端暂时断网或 5xx：保留本地 outbox，指数退避，恢复在线后先拉快照再续传。
- 权限、校验或资源不存在：停止自动重试，显示明确错误并以服务端快照校正本地投影。
- 生成重复回调：数据库原子门禁只允许首个完成者提交，失败方清理自身暂存对象。
- 新版本部署失败：按“前端 → Edge Function”顺序回滚，保留兼容性数据库函数与新增列，避免逆向破坏迁移。
- 契约或格式漂移：CI 直接阻断合并，不允许以忽略规则绕过。

## 测试与验收

优化完成的共同出口是：

- `npm run typecheck`、ESLint CLI、Prettier、生产构建全部通过且无警告豁免。
- Vitest、Deno Edge 测试与 Playwright 核心流程全部通过。
- 双页面 Realtime、断网恢复、刷新恢复、生成重复回调和 1,000 节点基准达到各专题文档定义的标准。
- 所有新增迁移均可在全新空 Supabase 项目上按顺序重建；不依赖测试环境业务数据。
- 设计真相文档与优化实施文档之间不存在契约冲突，交叉链接有效。
