# 优化总览与实施路线

## 目标

本轮优化以“核心稳定优先”为总目标：先恢复主页创建、设计页对话、画布编辑、异步生成、实时回流和可靠保存组成的完整闭环，再治理性能和工程质量，最后才扩展非核心产品能力。

本文给出统一优先级、实施阶段和放行门禁。详细问题证据见[《现状审计与问题清单》](./01-现状审计与问题清单.md)，各领域的实现细节由后续专题文档定义。

## 现状问题

项目可以完成类型检查和生产构建，主页、项目创建、画布、Supabase 数据层、生成适配器和部署脚本已经具备可运行基础；但“能够运行”尚不等于“可稳定上线”。当前最关键的断点是：

1. 对话组件已实现但未挂载到设计工作台，ChatStore 未随项目数据水合，消息 Realtime 未订阅。
2. 防抖保存缺乏单飞与可靠重试，失败 upsert 会从脏集合消失；离线、重连和长会话媒体刷新缺少闭环。
3. 生成创建是多步写入，结果落库缺少事务内终态门禁；轮询与 webhook 竞态可能产生重复资产或节点。
4. 类型契约重复维护，Edge 代码不在 TypeScript 和 ESLint 当前覆盖范围内，Prettier 基线失败，自动化测试为空。
5. 节点级重复查询、逐节点数组扫描、全量历史快照和全量媒体扫描会在大画布放大。

这些问题会分别造成核心功能不可见、编辑数据丢失、生成结果重复、安全边界放大、契约漂移和性能退化，因此必须在继续扩展功能前收敛。

本节保留的是 2026-08-25 改造前基线；当前关闭状态与验证结果见“实施状态与证据”。

## 实施方案

### 优化原则

- **设计真相不旁路**：现有 `docs/00–06` 继续定义产品与架构，本目录只记录实现差距、整改顺序与验收证据。
- **数据库为唯一真相**：Zustand、Realtime 和 IndexedDB 都是数据库投影；冲突通过服务端快照和明确的本地未提交集合处理。
- **先可靠再提速**：先消除丢写、重复落库和未鉴权调用，再建立性能预算，避免把竞态隐藏在批处理内。
- **兼容性优先**：HTTP 封套保持兼容；数据库使用可前向部署的新增函数、索引和列，客户端切换后再收口旧路径。
- **验收可自动化**：每个改动都必须有失败路径和可重复测试，不以人工“看起来正常”作为唯一结论。
- **环境可重建**：全新空 Supabase 项目只依靠迁移、种子和函数恢复结构，不搬运业务数据、Auth 用户、Storage 对象、Docker 卷或环境文件。

### 优先级

| 优先级 | 范围                                                                             | 完成标准                                               |
| ------ | -------------------------------------------------------------------------------- | ------------------------------------------------------ |
| P0     | 对话链路装配、保存不丢写、生成只落库一次、内部函数鉴权、基础质量门禁             | 端到端主链路可重复通过；竞态、断网和权限测试可证明边界 |
| P1     | Realtime 重连校正、差异式撤销、签名 URL 续签、批量节点更新、共享模型与凭据数据源 | 双页面与离线恢复通过；1,000 节点基准无功能性退化       |
| P2     | 导出入口、真实分享权限、版本浏览、AI 文本生成等产品完整度能力                    | P0/P1 稳定后单独立项，并先更新设计真相文档             |

### 阶段顺序

1. **阶段 A：冻结基线。** 固化当前检查结果、核心流程、数据库迁移版本和性能测量方法。
2. **阶段 B：恢复工作台闭环。** 水合 ChatStore、挂载可折叠对话面板、接入消息与生成 Realtime，并在重连时做快照校正。
3. **阶段 C：收敛可靠性与安全。** 引入串行持久化、IndexedDB outbox、原子生成 RPC、结果单次提交和内部 service-role 鉴权。
4. **阶段 D：治理交互与性能。** 改造差异式历史、批量节点更新、签名 URL 续签和工作台级共享数据源。
5. **阶段 E：建立质量门禁。** 统一契约生成，补齐 Vitest、Deno、Playwright、并发与性能测试，在 CI 中强制执行。
6. **阶段 F：灰度与验收。** 按数据库、Edge Function、前端顺序部署，观察错误率、outbox 积压、生成耗时和重复回调指标后放量。

阶段之间使用硬门禁：前一阶段的自动化验收未通过，后一阶段不得用于生产放量。

## 实施状态与证据（2026-08-25）

阶段 A 至 E 已在仓库本地实现：对话主链路、可靠保存、生成事务、安全边界、性能热点和质量门禁均已落地。阶段 F 中可自动执行的本地验收已经接入 `npm run check`；预发布部署、生产监控和观察窗口属于发布环境工作，未以本地结果替代。

本轮证据包括 36 个 Vitest、9 个 Deno Edge 测试、31 个 pgTAP、20 轮并发 submission 与 20 轮并发 landing、6 条 Playwright 任务以及 100/500/1,000 节点性能场景。全新影子数据库可以顺序应用第 1–26 号迁移，`supabase db diff --local --schema public` 返回零 schema 差异。

具体实现与证据分别记录在[对话与实时同步](./02-对话与实时同步优化.md#实施状态与证据2026-08-25)、[画布可靠性与性能](./03-画布可靠性与性能优化.md#实施状态与证据2026-08-25)、[生成事务与安全](./04-生成事务与安全优化.md#实施状态与证据2026-08-25)、[类型契约与工程质量](./05-类型契约与工程质量.md#实施状态与证据2026-08-25)和[测试计划](./06-测试计划与上线验收.md#本地验证证据2026-08-25)中。

## 接口变化

阶段 B 新增工作台同步状态、对话面板展开状态和带 `conversationId` 的项目订阅接口；阶段 C 新增客户端 outbox 契约以及 `create_generation_submission`、`land_generation_result_once` 数据库函数；阶段 D 新增批量节点更新与带到期时间的媒体视图；阶段 E 新增契约生成和检查脚本。

这些变化的命名与职责由对应专题文档锁定。现有对外 Edge Function 路径、请求体主字段、响应封套与数据库枚举字面量保持不变，避免客户端和后台任务必须同时升级。

## 失败处理

每个阶段都必须支持独立停止和回滚：

- 数据库先部署兼容性函数，不立即删除旧函数；回滚应用时继续保留新函数和列。
- Edge Function 在切换新 RPC 前保留对旧数据形态的读取能力；一旦写入成功，不通过应用回滚删除业务结果。
- 客户端新同步逻辑出现异常时，可以回滚前端版本；已写入的 outbox 记录保留并由兼容版本读取或通过恢复工具导出。
- 监控到重复生成、权限绕过或持续丢写时停止放量，禁止用扩大重试次数掩盖根因。

## 测试与验收

总体验收要求如下：

- 新用户可从主页创建项目，进入设计页后可立即看到画布与对话面板，并完成一次不调用真实付费模型的模拟生成闭环。
- 编辑期间断网、刷新、重连及两个页面同时打开时，节点、消息和生成状态最终一致，未确认写入不会静默丢失。
- 同一生成任务被 webhook 与轮询并发完成时，数据库只产生一组业务结果，失败方清理自身暂存对象。
- 未持有内部 service-role 凭据的请求无法触发队列处理与轮询批任务。
- 全量静态检查、格式检查、单元测试、Edge 测试、端到端测试和生产构建在 CI 通过。
- 1,000 节点基准场景下拖拽、框选、批量移动和缩放保持可操作，且不会产生按节点数线性增长的模型目录或凭据请求。
