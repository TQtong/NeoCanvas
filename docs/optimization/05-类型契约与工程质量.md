# 类型契约与工程质量

## 目标

建立可以在本地和 CI 重复执行的完整质量基线：根 `types/` 是浏览器、Next.js 服务端与 Supabase Edge Function 的唯一业务契约源；生成文件可验证、格式统一、前端与 Deno 都能静态检查，任何警告、契约漂移或测试失败都会阻断合并。

## 现状问题

- 根 `types/` 和 `supabase/functions/_shared/types.ts` 重复声明枚举与请求/响应类型，当前依靠人工评审保持一致，与“共享类型单点”的工程约束冲突。
- Deno 要求显式扩展名和不同的模块解析方式，根前端配置又排除了 `supabase/functions`，导致现有 `npm run typecheck` 无法发现 Edge 契约错误。
- `.eslintrc.json` 同样忽略 Edge Function；`npm run lint` 仍调用 Next.js 15 已弃用的 `next lint`，且允许一条 `<img>` 警告通过。
- `npm run format:check` 当前报告 52 个文件漂移，格式检查不能作为有效门禁。
- 模型目录与 Provider 凭据由节点组件各自获取，没有工作台级共享数据源，也缺少统一缓存与刷新契约。
- 项目没有 Vitest、Deno test 或 Playwright 配置，现有 build 成功不能覆盖运行时竞态与失败恢复。

本节保留优化前工程基线；当前实现状态见“实施状态与证据”。

## 实施方案

### 1. 根 `types/` 单一契约源

根 `types/` 继续承载数据库枚举、节点判别联合、生成请求/响应、错误码、Realtime payload 和视图模型。契约按以下规则组织：

- 纯类型文件不得导入 React、Next.js、Node 专用 API或运行时副作用。
- 数据库枚举字面量与迁移逐字一致，禁止在 Edge 侧单独增加同义值。
- 对外请求与响应通过 Zod schema 或等价的可生成结构定义，TypeScript 类型从 schema 推导，避免验证器与声明再次分叉。
- 浏览器专用视图状态与数据库行类型分离，但映射函数只在 `lib/canvas` 等既定边界实现。

### 2. Edge 契约生成与漂移检查

新增确定性生成脚本，从根契约入口生成 `supabase/functions/_shared/contracts.generated.ts`。生成结果满足 Deno 的显式 `.ts` 导入要求，并带有“由脚本生成、禁止手改”的文件头。现有 `_shared/types.ts` 改为从生成文件导出，业务 Edge Function 不直接复制声明。

生成流程必须满足：相同输入产生字节完全一致的输出；生成文件由 Git 跟踪；CI 先运行生成命令，再用 `git diff --exit-code` 检查漂移。生成器无法表达的运行时代码保留在手写 `_shared` 模块中，但其输入输出必须引用生成契约。

Deno 的共享代码放在 `_shared`，检查每个函数入口，遵循 Supabase 官方的[共享代码组织](https://supabase.com/docs/guides/functions/import-maps#using-import-maps)与[Deno 本地开发建议](https://supabase.com/docs/guides/functions/local-development)。

### 3. ESLint、Prettier 与 Deno Check

将前端 lint 脚本切换为 ESLint CLI，例如：

```text
eslint . --ext .ts,.tsx --max-warnings=0
```

配置显式排除构建产物和生成文件，同时覆盖 `app/`、`components/`、`stores/`、`lib/`、`types/` 与脚本目录。Edge Function 使用 `deno lint` 与 `deno check`，避免把 Deno globals 强行塞入浏览器 ESLint 环境。

先单独执行一次仓库格式基线修复并评审，之后 `prettier --check` 作为强制门禁。生成文件由生成器保证格式，不由人工编辑。`Avatar` 的图片警告和 middleware 的 Edge Runtime import trace 必须按实际运行边界修复，不能通过关闭规则或忽略警告消音。

### 4. 模型目录与凭据共享数据源

在主页和设计工作台各自建立一次性领域数据源，统一加载：

- 当前用户可见且 enabled 的 model catalog。
- Provider 凭据的非敏感可用状态，不包含明文密钥。
- 场景、modality、排序与默认模型解析结果。

工作台通过精确 selector 向 ChatPanel、工具栏和 MediaPanelNode 分发，只在设置保存成功、Realtime 目录变更或显式刷新时重新请求。节点不能自行发起目录/凭据查询。共享源以用户 id 作为缓存边界，退出登录立即清除，避免跨用户复用。

### 5. CI 质量门禁

统一 `npm run check` 按下列顺序执行，任何一步失败即停止：

1. 契约生成与 `git diff --exit-code` 漂移检查。
2. `prettier --check`。
3. ESLint CLI `--max-warnings=0`。
4. `tsc --noEmit`。
5. Vitest 单元与组件测试。
6. `deno fmt --check`、`deno lint`、所有函数入口 `deno check` 和 Deno 测试。
7. Next.js 生产构建。
8. Playwright 核心端到端测试。

CI 固定 Node、Deno、Supabase CLI 和浏览器版本，缓存只能加速依赖安装，不能缓存检查结论。日志与测试工件需要脱敏。

## 接口变化

建议新增脚本职责如下，最终命名在实现时统一写入 `package.json`：

| 脚本                 | 职责                                              |
| -------------------- | ------------------------------------------------- |
| `contracts:generate` | 从根契约生成 Deno 兼容文件                        |
| `contracts:check`    | 生成后检查 Git 漂移                               |
| `lint`               | ESLint CLI 且不允许 warning                       |
| `functions:check`    | 对全部 Edge Function 入口执行 Deno fmt/lint/check |
| `test`               | Vitest 非 watch 模式                              |
| `test:edge`          | Deno 单元与集成测试                               |
| `test:e2e`           | Playwright 核心流程                               |
| `check`              | 编排全部合并门禁                                  |

模型与凭据共享源返回只读结构：

```ts
interface WorkbenchModelSource {
  models: ModelCatalogEntry[];
  credentialAvailability: Record<string, boolean>;
  loading: boolean;
  error: string | null;
  refresh(): Promise<void>;
}
```

API 密钥、Vault secret id 和 service-role 信息不进入该接口。Edge 契约文件属于构建产物式源码，只能由生成命令修改。

## 实施状态与证据（2026-08-25）

- [`generate-edge-contracts.mjs`](../../scripts/generate-edge-contracts.mjs) 从根 [`types/`](../../types/) 生成 Deno 兼容的 [`contracts.generated.ts`](../../supabase/functions/_shared/contracts.generated.ts)；`contracts:check` 做字节级漂移检查，Edge 手写类型只组合生成契约。
- `lint` 已切换 ESLint CLI 并启用 `--max-warnings=0`；`format:check` 覆盖约定的 TS/TSX/CSS/Markdown/JSON/MJS；`functions:check` 对 Edge 执行 Deno fmt、lint、入口 check 和测试。
- 根 `tsconfig` 只覆盖 Next/浏览器域并排除 Deno 专用目录；Deno 函数和数据库并发测试由同一固定 `deno.json` 在各自运行时完成严格类型检查，没有以根排除项跳过验证。
- 工作台以单一 Context 共享可见模型目录和脱敏凭据快照，设置事件统一刷新所有消费者，客户端接口不包含密钥或 Vault 标识。
- [`quality.yml`](../../.github/workflows/quality.yml) 在 Node 20、本地 Supabase 和固定 Chromium 上运行完整 `npm run check`，失败时上传脱敏后的 Playwright/服务诊断工件。

统一门禁现包括契约、格式、ESLint、TypeScript、Vitest、Deno、数据库 lint、pgTAP、Deno 数据库并发、生产构建和 Playwright。依赖审计通过且无已知 npm 漏洞；准确测试计数见[测试计划](./06-测试计划与上线验收.md#本地验证证据2026-08-25)。

## 失败处理

- 契约生成失败或生成后有差异：CI 阻断，开发者先修改根契约或生成器，不能手改生成文件。
- Deno 与前端对同一 schema 推导不同：以根 schema 和数据库枚举为准，修复生成映射后重新生成，不在 Edge 侧添加临时类型断言。
- 格式基线修复与业务改动冲突：格式修复使用独立提交并先合入，后续分支重放，避免把 52 个历史漂移混进功能评审。
- 共享模型数据加载失败：保留上次同用户缓存并标记过期；没有可信缓存时禁用生成，不能退回到节点级重复查询。
- CI 环境缺少 Deno、浏览器或 Supabase 服务：视为流水线配置失败并阻断，不跳过相应任务。
- 生产构建警告：按失败处理，记录准确 import trace 并修复边界；不允许长期维护 warning 白名单。

## 测试与验收

- 修改任一根枚举或响应字段但不提交生成文件时，`contracts:check` 必须失败；重新生成后前端与 Deno 类型测试同时通过。
- 搜索确认 Edge Function 不再手工重声明根业务枚举，生成文件以外不存在第二份契约源。
- ESLint CLI 覆盖全部前端目录并以零 warning 退出；`next lint` 不再出现在脚本中。
- Prettier 对仓库约定范围全通过，新文档、迁移和配置文件格式一致。
- 每个 Edge Function 入口通过 `deno check`，共享模块通过 `deno lint`，测试可在固定 Deno 版本运行。
- 在含多个媒体面板的工作台中，模型目录和凭据状态各只有一个请求源；设置变更后所有消费者一致更新。
- `npm run check` 在干净检出、空缓存环境完整通过，失败步骤返回非零退出码且不泄露凭据。
