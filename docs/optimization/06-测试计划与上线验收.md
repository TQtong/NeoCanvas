# 测试计划与上线验收

## 目标

用分层、确定性、可在 CI 重复执行的测试证明核心稳定优化有效，并定义生产部署、观察和回滚的统一清单。测试不调用真实计费模型，生成结果由本地确定性 Provider 模拟器提供，以便稳定覆盖成功、失败、超时、重复回调和乱序事件。

## 现状问题

- 当前仓库没有 Vitest、Playwright 或 Deno 测试配置与用例，关键几何、Store、Edge pipeline 和用户旅程没有自动化保护。
- 类型检查与生产构建只能证明静态和打包基本成立，不能发现保存竞态、离线恢复、Realtime 漏事件、重复 landing 和权限绕过。
- 没有双页面协同、1,000 节点性能与 Storage 签名 URL 到期的固定复现环境。
- 上线流程缺少迁移、Edge Function、前端之间的分阶段放行证据，也没有与新事务函数兼容的回滚检查表。

本节保留优化前测试基线；当前自动化实现和执行结果见“本地验证证据”。

## 实施方案

### 1. 测试分层与数据策略

| 层级             | 工具                                      | 覆盖边界                                                       | 外部依赖                                   |
| ---------------- | ----------------------------------------- | -------------------------------------------------------------- | ------------------------------------------ |
| 单元/组件        | Vitest + React Testing Library            | 映射、几何、Store、历史、outbox、状态机、组件交互              | fake timers、内存 IndexedDB、mock Supabase |
| Edge 单元        | Deno test                                 | 鉴权、schema、适配器规范化、签名验证、幂等分支                 | 注入式 fake provider                       |
| 数据库/Edge 集成 | Supabase CLI + Deno test                  | RLS、RPC 事务、队列、行锁、并发 landing、Storage 补偿          | 本地 Supabase                              |
| 端到端           | Playwright                                | 登录后的主页创建、设计工作台、对话、画布、生成、刷新和离线恢复 | 本地 Next.js + Supabase + fake provider    |
| 性能             | Playwright trace + 浏览器 Performance API | 100/500/1,000 节点渲染与交互、请求数、内存趋势                 | 固定数据种子与浏览器版本                   |

测试数据由迁移、`seed.sql` 和测试专用 seed 构建。每个用例创建独立用户与项目 namespace，结束后只清理该 namespace。绝不复用生产或共享测试环境的 Auth 用户、业务行与 Storage 对象。

### 2. Vitest 单元与组件测试

至少覆盖：

- 数据库行与 7 类画布节点的双向映射、枚举和默认值。
- screen/flow 坐标转换、旋转包围盒、对齐线、缩放约束和批量几何变换。
- 生成血缘 DAG 的边创建、删除、候选切换与环路拒绝。
- CanvasStore/ChatStore 水合幂等、精确 selector、消息和 generation upsert 去重。
- 串行 flush、outbox 合并、clientRevision 确认、失败恢复、指数退避和重启重放。
- 操作事务历史覆盖内容、样式、旋转、节点新增/删除、边和批量更新。
- Realtime 回声抑制、断线状态机、快照校正与本地未提交 mutation 重放。
- 签名 URL 到期前续签、401/403 续签、single-flight 和 timer 清理。
- ChatPanel 折叠不卸载草稿，标题更新失败回滚，无可用模型时禁止提交。

时间相关测试使用 fake timer，网络并发使用可控 Promise 与屏障，不依赖真实等待。

### 3. Deno Edge 与数据库测试

Edge 单元测试覆盖：JWT/service-role 区分、webhook 签名和重放窗口、模型归属、请求 Zod 校验、Provider 响应规范化与错误码映射。

本地 Supabase 集成测试覆盖：

- `create_generation_submission` 每个失败注入点的完整回滚。
- 同幂等键并发、请求摘要冲突、跨用户/跨项目作用域隔离。
- model catalog 内置与自定义所有权、凭据存在性和 modality 限制。
- `land_generation_result_once` 的行锁、终态门禁、资产/节点/边/消息原子提交。
- poller 与 webhook 并发、队列重复投递、迟到成功/失败/取消事件。
- staging 对象补偿只删除未引用且超过安全窗口的任务前缀。
- authenticated、anon 与错误 service-role 无法执行内部 RPC 或批处理函数。

并发用例至少重复 20 轮以提高竞态暴露概率，且每轮都验证精确行数、唯一约束、终态和 Storage 引用，而不是只检查 HTTP 200。

### 4. Playwright 核心端到端流程

主流程为：已认证用户打开主页 → 输入 prompt 并选择 fake model → 创建项目 → 进入设计页 → 同时看到画布占位和 380px 对话面板 → fake provider 完成 → 生成结果替换占位并出现在消息中 → 刷新后状态保持。

补充流程包括：

- 新建会话、发送消息、切换会话、折叠/恢复面板和即时重命名。
- 文本、形状、媒体节点的新增、移动、缩放、旋转、删除及撤销/重做。
- 编辑后立即离线，继续移动和改文案，刷新/重开页面后恢复 outbox，联网后最终保存。
- 媒体 URL 过期、续签失败一次后恢复，节点与资产关系不丢失。
- Provider 失败、超时、取消与重试，消息和占位显示准确终态。
- 无可用模型、项目无权限、会话不存在和附件上传失败的可恢复界面。

所有生成使用固定输入得到固定测试图片/视频元数据，不调用 OpenAI、Google、Ark、SiliconFlow、fal.ai 或 Replicate 的真实付费接口。

### 5. 双页面 Realtime 与离线恢复

使用两个独立浏览器 context 登录同一测试用户并打开同一项目：

1. 页面 A 移动节点，页面 B 在 Realtime 内收到最终位置且不产生回声写回。
2. 页面 B 发送消息，页面 A 的当前 conversation 顺序一致且只出现一次。
3. fake provider 同时触发 webhook 与 poller，两个页面都只看到一个 generation 完成结果。
4. 断开页面 A 网络，页面 B 修改同一实体和另一个实体；页面 A 离线修改后恢复。
5. 校正算法依据服务端快照与 outbox revision 合并，永久冲突被明确展示，非冲突修改全部保留。

最终以数据库行、两个页面 Store 投影和 IndexedDB outbox 三方断言：已确认实体一致，outbox 为空，消息与资产无重复。

### 6. 千节点性能测试

固定生成 100、500、1,000 个包含文本、图片、形状和媒体面板的节点数据集。每档执行冷加载、平移、连续缩放、单节点拖拽、50 节点批量移动、撤销/重做和媒体续签。

记录以下指标：

- 首次可交互时间与长任务数量。
- 操作期间主线程帧耗时、React 提交次数和 Store 更新次数。
- JS heap 峰值与操作结束后的稳定值。
- PostgREST、Storage 签名和模型/凭据请求数量。
- 持久化批次数、单批实体数与 outbox 清空时间。

硬性结构验收为：50 节点批量移动只触发一次 Store 批量更新和一个历史事务；模型目录与凭据每个工作台各一个请求源；位置拖拽不触发媒体续签请求。帧率和耗时阈值在首次基线报告中按 CI 性能机确定，后续提交相对基线退化超过 15% 即阻断。

### 7. CI 与上线顺序

CI 依次执行契约漂移、格式、Lint、前端类型、Vitest、Deno fmt/lint/check、Deno 测试、生产构建和 Playwright。主分支合并必须全部通过。

生产部署顺序：

1. 备份并记录当前迁移版本、Edge Function 版本和前端镜像摘要。
2. 在全新空 Supabase 验证完整重建，再在预发布环境运行全部测试。
3. 部署兼容性数据库迁移，验证新函数权限、索引、队列和旧读取路径。
4. 部署 Edge Function，先让内部测试项目走新 RPC，观察错误和幂等指标。
5. 部署前端，逐步扩大使用范围，重点观察保存失败率、outbox 积压、Realtime 重连、生成 landing 冲突与 staging 清理。
6. 完成一个签名 URL 生命周期和异步生成最大合理时长的观察窗口后宣布放行。

## 接口变化

测试基础设施新增确定性 fake provider、测试数据工厂、并发屏障和 Playwright 认证状态。fake provider 实现与生产适配器相同的 submit/query/normalize 接口，但只在本地与 CI 环境注册；生产构建检测到测试 Provider 配置时必须拒绝启动。

CI 输出 JUnit、Playwright trace、失败截图、Deno 日志摘要和性能 JSON。工件中只允许测试用户和虚构 token，统一脱敏 Authorization、Cookie、Provider payload 与 Storage 签名参数。

测试接口不会改变公开业务 API。为故障注入增加的开关只能通过测试环境变量启用，并在生产启动校验中明确禁止。

## 失败处理

- 测试不稳定：先修复竞态或测试隔离，不能通过无限重跑宣布通过；允许保留一次诊断重试，但初次失败仍计入稳定性指标。
- 本地 Supabase 初始化失败：停止集成与 E2E，保留服务日志和迁移版本，不回退为全 mock 后放行。
- 数据清理失败：按测试 namespace 报警并停止复用环境，禁止扩大清理到工作区或共享项目。
- 性能回归：保存 trace 和指标差异，确认机器噪声后仍超过 15% 则阻断。
- 灰度出现持续丢写、重复 landing、权限绕过或迁移异常：立即停止放量，先回滚前端，再回滚 Edge Function；兼容性数据库新增结构保留，避免破坏已写数据。
- outbox 协议导致客户端无法读取：回滚前端前提供兼容读取或恢复导出，不能清空用户未确认编辑。

## 测试与验收

上线前必须逐项满足：

- [x] 设计真相文档与优化文档一致，所有 P0/P1 问题均有对应自动化用例和验证证据。
- [x] `npm run check` 在本地固定工具链中完整通过，格式、Lint 与构建无 warning 豁免。
- [x] Vitest 覆盖映射、几何、DAG、Store、历史、持久化、Realtime 和签名 URL。
- [x] Deno 与本地 Supabase 覆盖鉴权、模型归属、事务回滚、幂等和并发结果落库。
- [x] Playwright 主流程、对话、双页面 Realtime、离线/刷新恢复和失败态全部通过。
- [x] 1,000 节点结构与性能门禁通过，报告包含可比较的环境信息和原始指标。
- [ ] 全新空 Supabase 项目只用迁移、种子和函数即可重建，不包含测试环境业务数据。
- [ ] GitHub Actions 在干净检出中执行同一质量门禁并保存诊断工件。
- [ ] 预发布环境完成数据库 → Edge → 前端部署演练，回滚版本与操作人明确。
- [ ] 监控可见保存失败、outbox 积压、Realtime 重连、生成耗时、幂等命中、landing 冲突和 staging 清理。
- [x] 本地自动化不调用真实计费模型，日志和测试报告不包含真实 Provider 凭据。

全部检查完成且观察窗口内无 P0/P1 异常后方可正式放行。若任一项失败，保持当前稳定版本并按对应专题的失败处理修复，不能以人工确认替代门禁。
