# AI 能力与生成服务设计

## 一、设计目标

AI 服务层把「多家提供商、多种模态、同步与异步并存」的外部模型生态，收敛为一套对上层稳定、对内可扩展的生成能力。它要达成三个目标：统一——上层（对话面板、画布工具）调用生成时面对的是统一语义，而非各家差异；隔离——外部密钥与调用细节封闭在边缘层，绝不外泄；可靠——异步任务有排队、有轮询、有回调、有超时与重试，结果不丢、状态不卡。这一层是产品「让设计更简单」承诺在能力侧的支撑。

## 二、多模型适配器抽象

核心是「模型适配器（Model Adapter）」模式：每个外部模型 / 提供商被封装为一个实现统一接口的适配器，编排层只依赖该接口，不感知具体提供商。适配器对上暴露三组语义。

**提交（submit）**：接收一份归一化的生成请求（模态、模型键、提示词、参数、参考素材引用），向提供商发起一次生成。对同步型模型，提交在一次调用内返回最终产出；对异步型模型，提交返回提供商侧的外部任务号，产出稍后获取。

**查询（poll）**：对异步型模型，依据外部任务号向提供商查询当前状态与进度，可能返回运行中（含进度）、成功（含产出）或失败（含原因）。同步型模型无需此语义。

**归一化（normalize）**：把提供商各异的产出（直返二进制、临时 URL、Base64、多产出列表等）统一转换为系统内部的「资产候选」描述——包含媒体的获取方式、模态、尺寸 / 时长等元信息，供流水线统一地取回、入 Storage、建资产。

适配器还声明自身的能力画像（支持的模态、可选比例与尺寸、单次最大产出数、是否支持参考图 / 图生图 / 图生视频、是否异步），这份画像与数据库 `model_catalog` 的 capabilities 对齐，既用于驱动前端的参数 UI，也用于流水线的请求校验。

适配器之上有一个**适配器注册表 / 路由器**：依据请求中的 `provider` 与 `model_key` 选取对应适配器实例。新增模型即「实现一个适配器 + 注册 + 在 `model_catalog` 追加一行」，核心流水线零改动。

## 三、提供商适配要点

系统当前实现六类提供商适配器，覆盖图像与视频两种主模态。模型是否展示与可用由
`model_catalog` 的活跃状态、节点模态与能力要求、用户启用的 BYOK 凭证共同决定。

**OpenAI — GPT Image 2（图像）**：作为主页默认选中的图像模型，对接 OpenAI 的图像生成接口，支持文生图与（按能力）参考图编辑，多为同步返回。适配器负责把统一请求映射为其参数（尺寸、质量、数量），并把返回的图像归一化为资产候选。

**Google — Nano Banana Pro（图像）**：对接 Google 侧的图像生成 / 编辑能力，擅长高保真与图像编辑类任务，支持以参考图为条件生成。适配器处理其鉴权方式与产出格式，归一化为资产候选。

**火山方舟 Volcengine Ark（视频与图像）**：对接火山方舟的 Seedance 2.0 视频生成与 Seedream 图像生成。Seedance 2.0 为典型异步模型——提交后得到外部任务号，需轮询任务直至产出视频；Seedream 为图像生成。适配器须妥善处理其异步任务的提交与查询语义、产出文件 URL 的可访问性与时效（取回后转存 Storage，避免依赖外部临时链接）、以及其参数体系。这是异步流水线（第五节）最典型的适用对象。

**SiliconFlow（图像与视频）**：当前目录包含 Kolors、Qwen Image、Z-Image、ERNIE Image 与
Wan 2.2 等模型，覆盖文生图、图片编辑、文生视频和图生视频。模型端点 ID 由
`model_catalog.default_params.providerModel` 驱动，适配器按能力画像选择同步或异步流程。

**fal.ai / Replicate（聚合平台）**：两类适配器均已注册，作为快速接入更多开源 / 第三方模型的
通道。它们以「提交任务 → 轮询 / 回调取结果」为主，天然契合异步流水线；具体模型仍需在
`model_catalog` 中登记并启用后才会出现在前端。

无论提供商为何，适配器层对外都只呈现统一的提交 / 查询 / 归一化语义，差异完全内化。

## 四、生成模态与参数

系统支持图像、视频、文本三种模态。图像生成的统一参数含提示词、负向提示（按模型支持）、宽高或比例、产出数量、质量档、参考图引用（用于图生图 / 编辑 / 风格参考）、随机种子。视频生成的统一参数含提示词、时长、分辨率、首帧 / 参考图引用（图生视频）、运动强度等（按模型支持）。文本 / 文案生成的统一参数含提示词与生成约束。各模型实际支持的参数子集由其能力画像声明，前端据此动态渲染参数控件，流水线据此校验并对不支持的参数做合理降级或拒绝。`@` 提及的画布节点与上传附件被解析为参考素材引用，按模型能力作为参考图 / 首帧传入。

## 五、生成流水线

生成流水线把一次生成请求从提交到落画布的全过程编排为可靠的异步流程，依托 Supabase 的 Edge Functions、Queues、pg_cron、Database Webhooks 与 Realtime 协同。

**提交阶段**（提交生成的 Edge Function）：校验调用者身份与项目归属；按模型能力校验请求参数；在 `generations` 表创建一条 pending 任务（含模态、模型键、提供商、提示词、参数、幂等键）；在画布上创建一个生成占位节点并与该任务互相关联；把任务投入 Supabase Queues 的待处理队列。函数返回后，客户端立即看到对话进行态与画布占位。幂等键确保同一请求重复提交不会产生重复任务。

**执行阶段**（消费队列的 Edge Function）：从队列取出待处理任务，置为 running；经适配器路由选定提供商适配器并提交生成。对同步模型，提交即得产出，直接进入完成阶段；对异步模型，记录返回的外部任务号、保持 running、等待轮询或回调推进。

**推进阶段**（两条途径并行兜底）：其一，pg_cron 定时触发轮询型 Edge Function，批量拉取处于 running 且为异步的任务，经适配器查询语义向提供商查进度，回写 `generations.progress` 与状态；其二，对支持回调的提供商，由回调型 Edge Function 接收其完成通知，按外部任务号反查任务并推进。两条途径互为兜底：回调缺失或丢失时轮询仍能推进，轮询间隔内的及时完成由回调更快反映。

**完成阶段**（结果落库的 Edge Function 逻辑）：经适配器归一化取得资产候选；把媒体取回并写入 Storage 的 generations 桶（视频 / 图片各按路径规范），生成缩略图；在 `assets` 建资产记录；把画布上的占位节点原地转化为对应的图片 / 视频节点（改写 type、填入 asset_id、替换 data），多产出时首张落占位、其余在占位附近新建节点；把任务置 succeeded、写 completed_at。这组写入处于一致的事务边界内，落库后由 Realtime 把节点与任务变更推回客户端，画布占位即更新为成品、对话进行态即转完成。

**失败与超时**：提供商报错或归一化失败时，任务置 failed、记录原因、占位节点转为可重试的失败态；pg_cron 兜底扫描长时间停滞的 running 任务判定超时，同样置 failed。失败任务允许用户一键重试（以原参数新建任务），不复用已失败记录以保审计清晰。

## 六、异步任务处理要点

异步是本层最易出错处，设计强调五点。**幂等**：提交以幂等键去重，推进与完成以「状态机单向转移」防止重复落库（已 succeeded 的任务忽略迟到的完成事件）。**进度**：轮询与回调持续回写进度，前端占位节点据此给出真实进度而非空转。**取回转存**：提供商返回的产出 URL 多为临时链接，完成阶段必须把媒体取回转存到自有 Storage，画布与资产只引用自有存储，杜绝外链失效导致的图裂。**超时与重试**：每类任务设合理超时，超时即失败；对可重试的瞬时错误（网络抖动、限流）在执行阶段做有限次自动重试与退避，超过上限才置失败。**回声与一致**：完成阶段的多处写入（Storage、assets、canvas_nodes、generations）保持事务一致，Realtime 回流到发起端时配合客户端的回声抑制，避免对自身刚提交的占位做无谓重置。

## 七、智能体编排

右侧对话面板背后的「Agent」承担把自然语言意图翻译为生成与画布操作的编排职责，运行于编排型 Edge Function，按所选 Agent 模式呈现不同深度。

**纯生成模式**：把用户消息与所选模型、参考素材直接映射为一次生成提交，是最直接的链路，等价于「对话即文 / 图 / 视频生成」。

**编排式智能体模式**：先以一个语言模型理解用户意图（要生成什么、要对画布上哪个元素做什么、要几张、什么风格），再决定调用哪些能力，可能形成多步序列——例如「先生成四个方向的图、再挑其中一张生成视频」，或「以画布上被提及的图为参考、换一种配色再生成」。编排器据意图组织一到多次适配器调用，并决定结果在画布上的落位（如四张图以网格排布）。编排过程对用户以对话回复 + 画布变化的形式可见。

**场景流程模式**：对应主页的 Design / Branding / E-Commerce / Video 场景，编排器加载该场景预置的提示词模板与画布初始结构，引导用户按场景化流程产出成套物料（如品牌场景产出标志、配色、应用示例的一组节点）。

无论何种模式，`@` 提及的画布节点都被编排器解析为上下文 / 参考素材随调用传入，使「针对画布上具体元素的再生成 / 编辑」成为一等能力。编排器对外的结果（文本回复经流式返回、图 / 视频经生成流水线异步落画布）统一汇入对话与画布，时序由对话状态库协调。语言模型本身亦经适配器接入，可在不同 LLM 间切换。

## 八、内容安全

生成入口对接内容安全审核，覆盖输入与产出两端。输入端对提示词、参考图做合规检查，拦截明显违规的请求；产出端对生成结果做必要的安全过滤（依提供商与自有策略），违规产出不落画布并向用户说明。各提供商自带的安全策略被尊重并叠加在自有策略之上。审核结果与拦截原因记录于生成任务，供审计与申诉。安全策略以可配置方式维护，便于按地区与合规要求调整。

## 九、可观测性

每次生成的关键节点（提交、入队、执行、各次轮询 / 回调、完成 / 失败）都产生结构化日志与指标，包含模型键、提供商、模态、各阶段耗时、产出数、失败原因。据此可观测各模型的成功率、时延分布与失败构成，定位卡顿任务与异常提供商，为容量决策提供依据。Edge Function 日志与指标在 Supabase 控制台观测并可汇出到第三方监控。`generations` 表本身即一份可查询的生成账本。

## 十、扩展新模型

新增一个模型 / 提供商的标准动作是：依统一接口实现其适配器（提交、查询、归一化、能力画像），在适配器注册表登记，在 `model_catalog` 追加一行（声明键、展示名、提供商、模态、能力画像、默认参数、排序与上架）。前端的模型选择条与参数 UI、流水线的校验、对话面板的模型切换都由模型目录数据驱动，因而自动纳入新模型，核心流水线与界面代码无需改动。这一「以适配器 + 配置驱动扩展」的设计，使产品能以最低成本持续跟进快速演进的模型生态。

## 十一、精准图片编辑 Provider 能力（v0.2.0 当前状态）

每个 Adapter 以不可由目录扩大的 `supportedOperations` 声明协议能力；运行时可用能力等于 Adapter 声明、`model_catalog.capabilities.imageOperations` 与当前用户启用凭据的交集。入口和 Edge 校验使用同一能力字面量，未通过交集的操作返回 `unsupported_operation`，绝不把语义编辑静默冒充局部重绘。

| Provider        | 当前开放的图片能力                                                                      |
| --------------- | --------------------------------------------------------------------------------------- |
| OpenAI          | `generate`、`semantic_edit`、`inpaint`、`outpaint`                                      |
| Google Gemini   | `generate`、`semantic_edit`                                                             |
| Volcengine Ark  | `generate`、SeedEdit `semantic_edit`                                                    |
| Jimeng          | `generate`、参考 `semantic_edit`、`inpaint`、`outpaint`、`remove_background`、`upscale` |
| MiniMax         | `generate`、人物主体参考 `semantic_edit`                                                |
| SiliconFlow     | `generate`；目录中经过验证的编辑模型可开放 `semantic_edit`                              |
| fal.ai          | `inpaint`、`remove_background`、2×/4× `upscale`                                         |
| Replicate       | 受控 Profile 提供 `inpaint`、`remove_background`、`upscale`                             |
| 自定义 Provider | 内置协议能力与用户模型声明的交集                                                        |

OpenAI 图片编辑使用 multipart：源图片按 `image[]` 传入，蒙版单独使用 `mask`；标准亮度蒙版在 Adapter 边界转换为透明 Alpha 编辑区。扩图输入由透明输出画布表达，不伪造不存在的四边 action。Google、MiniMax 与 SiliconFlow 只声明已经验证的参考/语义编辑能力，不声明像素级蒙版。Volcengine Ark 仅让 SeedEdit 路径消费源图。

Jimeng 的参考编辑、重绘、扩图、去背景和放大分别映射到官方专用 action，并按 action 校验提示词、蒙版、输出画布或倍率。fal.ai 直接映射已登记工具端点；Replicate 只能选择代码内受控 Profile，Profile 固定版本、输入字段、输出解析和能力，用户目录不得提供任意模型版本或任意字段映射。

Provider 调用共用超时、AbortSignal、响应状态校验、输出 URL/二进制解析、图片尺寸与透明通道验证、内容安全和错误归一化。鉴权、限流、上游 4xx/5xx、超时、无结果、输出尺寸错误和透明输出错误都转换为共享稳定错误码；日志与 generation 账本保留 operation、provider、model、完成时间、输入参数和不含临时地址的输出尺寸摘要。

启用一个真实模型前必须以目标环境凭据完成至少一次成功请求和一次可预期错误请求。冒烟失败只移除该模型对应 operation，不影响同 Provider 其他模型或普通 `generate`；关闭前端特性开关也不会绕过 Edge 端能力校验。
